# Avalonia 桌面界面

读取项目 UI 入口、主题资源、正式控件与现有 AXAML/视图模型，再按 [面向用户设计](../design-for-users/SKILL.md) 明确每屏主任务。项目已有布局与 MVVM 模式优先，不为小改动另加框架。

## 布局与交互

- 核对 Grid/Panel 的尺寸归属、最小最大值、拉伸和滚动边界；在支持的窗口尺寸与系统缩放下检查长标题、文案、路径、空态和密集数据。
- 字体、颜色、间距、图标与控件状态复用主题资源；深色、固定圆角、导航结构与品牌色属于产品选择，不作为通用要求。
- 检查键盘焦点、Tab 顺序、快捷键、可访问名称与对话框返回焦点。状态变化不抢走输入，禁用原因可理解。
- 大量记录按需加载并限制实际控件数量，核对虚拟化是否生效；不能因外层滚动或自定义模板失去虚拟化后仍声称性能合格。

## 数据与生命周期

按 [编程设计](../programming-design-style/SKILL.md) 复用正式查询与命令，ViewModel 保存可重建展示状态。通知、绑定、事件订阅、异步取消和窗口销毁成对处理；重开窗口后旧请求不得更新新实例。

后台工作和 UI 提交遵循项目现有线程调度。保存、加载、错误和取消按 [流畅交互](../design-responsive-interactions/SKILL.md) 设计，保留有效内容与输入，避免通过全窗口禁用遮掩状态问题。

## 验证

运行项目现有构建和绑定检查入口，检查实际资源解析及绑定错误。启动隔离的测试实例观察最后修改后的真实窗口，覆盖目标窗口尺寸、系统缩放、长文案、滚动、键盘焦点、关闭重开及相应失败状态。构建通过不等于界面与交互通过；不能启动时明确未验证的部分。
