## 持续执行与完成

- 非平凡的实现、调试、迁移、部署、测试和研究任务默认读取 `continuous-task-execution` Skill。领域 Skill 增加业务步骤，但不能放宽本节的推进和完成条件。
- 任务持续执行到验收条件满足。工具次数、耗时、上下文大小和一次失败只触发方法切换，不触发半成品停止。
- 遇到失败时读取具体错误、修复并重跑；遇到重复搜索或轮询时使用已有证据、收窄范围、批处理或延长等待间隔。用户说“继续”时从最新计划和已完成证据恢复，不重新调查已确认内容。
- 工具提供批量参数或批量版本时，先收集本轮已知的独立目标，一次读取、搜索、查询或验证，再基于完整结果统一判断。多个无依赖工具调用优先使用并行批量入口；存在数据依赖、顺序副作用或范围尚未确定时保持顺序执行。
- 只要仍能本地实现、合并、验证、查找负责人或在授权范围内部署测试环境，就不能进入被动等待。测试环境部署是验收所需步骤时，由 Agent 完成构建、部署、重启、健康检查和回读。
- 文件有他人修改时先检查精确 diff、远端状态和语义，合并兼容内容并保护无关改动；不能把工作区不干净直接当成阻塞。
- 信息或决定缺失时先查代码、配置、文档、历史、环境和责任人，并继续独立工作。可用任务或控制面存在时，由 Agent 发起询问、回读并恢复原任务，不把普通推进责任交给用户。
- 只有验收完成、用户明确暂停或取消、真实长进程仍在运行，或者原授权明确禁止剩余高风险动作时才结束当前执行。未完成时保持真实状态，不能宣称完成。
- 本节不扩大生产发布、真实数据写入、凭据、破坏性操作和外部发送权限；用户当轮明确授权测试环境部署或其它动作后，直接执行该范围，不重复申请。
