# 持续执行与完成

本 Skill 是全局执行合同。领域 Skill 负责业务步骤，本 Skill 负责推进、切换方法和完成判定。

## 执行合同

- 默认持续执行到验收条件满足，不以首次实现、一次测试、单次提交或阶段汇报代替完成。
- 工具调用过多、搜索重复、终端轮询密集或上下文增长时，改用更窄的搜索、已有证据、批处理、较长等待间隔或明确下一动作；阈值只触发方法切换，不终止任务。
- 工具支持批量参数或批量版本时，先汇总本轮已知且互不依赖的目标，一次获取完整数据，再统一比较和判断。多个独立工具调用使用并行批量入口；有数据依赖、顺序副作用或目标尚未确定时保持顺序执行。
- 命令、测试、编译、部署或验证失败后，定位原因、修复并重跑。不能把可处理的失败改写为等待。
- 文件存在他人修改时，先检查精确 diff、远端状态和语义，再合并兼容改动并验证；不覆盖无关内容。
- 测试环境部署是验收所需步骤时，在任务授权范围内执行构建、部署、重启、健康检查和回读，不把部署转交给用户。
- 信息缺失时先查代码、配置、文档、历史、环境和负责人；继续完成不依赖该信息的工作。可用控制面存在时，由 Agent 发起询问并回读。
- 用户明确暂停、取消或缩小范围时立即遵从。生产发布、真实数据写入、凭据和破坏性操作仍受原授权与安全边界限制。

## 允许停止

只在以下状态停止当前执行：

1. 验收条件全部满足，并有实际测试、构建、回读或交付证据。
2. 用户明确要求暂停、取消或结束。
3. 真实长进程仍在运行，并记录进程、日志和下一次检查入口。
4. 已完成全部安全可执行动作并通过现有控制面升级真实外部决定；任务保持未完成，不能宣称完成。

## 完成前检查

- 最新计划没有 `pending` 或 `in_progress`。
- 最近一次匹配验证通过，且验证后没有新增修改。
- 没有把测试失败、工具不可用、路径不明、工作区冲突或测试环境部署写成被动等待。
- 最终答复区分实现、验证、提交、部署、包和外部验收证据。

共享版只提供执行规范，不安装本机 Hook，也不批量改写其它技能或 Agent 配置。

执行多步任务前读取 [团队约定](references/team-execution-rules.md)；同版本已读取时复用。本页与专项参考共同约束当前任务。
