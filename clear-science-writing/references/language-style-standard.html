先看整体

文风由词汇、句式、段落和整篇编排逐层形成；阅读效果与证据状态贯穿四层。

用它把材料写成读者能顺着逻辑读懂、又不丢失事实边界的文章。内容模型决定说什么、哪些事实不能改变；语言风格决定同一内容怎样被命名、成句、分段和编排。词汇首先形成语言身份、关系距离和语域，句式、段落、整篇顺序、声音和表现策略再形成稳定的“声音指纹”。先封闭内容边界，再逐层提取文风。

先分清两种层级

分析时同时使用两张地图，不能把它们混成一组形容词。

第一张地图回答“写法出现在哪个文字层级”：

词汇选择 → 句式构造 → 段落结构 → 整篇编排

第二张地图回答“怎样从证据得到文风结论”：

可观察写法 → 推定阅读效果 → 跨样本稳定组合 → 场景适用性

“正式、亲近、强硬、克制、快速”属于阅读效果，不是与词汇、句式并列的写作层级。任何效果判断都要能回指实际用词、位置、句法、段落动作或顺序证据；任何稳定文风都要由多项共同出现的选择构成，不能由一个口癖、一个标点或一句典型文本定义。

还要分开容易混淆的轴：礼貌不等于要求较弱，判断确定不等于要求对方执行，情绪正负不等于情绪强弱，具体不等于精确，句子长不等于信息密度。完整分析规则见 references/nonlexical-style-extraction.md。

二、文风

1. 词汇是第一风格约束

提取文风时先完整阅读 references/lexical-extraction.md。其中的词类和例词只是搜索范围，不是提取答案。必须回到实际语料，逐类找出主要使用的词、较少使用的同义词、稳定搭配、常见位置和覆盖范围。语料没有出现的类别只留在通用候选检查结果中，不写入目标风格 Skill 的正式参数、字典或正文。

统计不能停在“出现多少次”。至少同时记录词频、标准化频率、样本覆盖率、句中位置、稳定搭配、承担功能、同义替代比例和对照组差异。单词相同但位置和作用不同，产生的文风也不同；例如“可以”可能表示许可、能力或可能性，必须按上下文分别统计。

语料较大时先运行词汇扫描；采样、匿名路径、JSONL、开放词汇和全文复核的完整规则只保存在 references/lexical-extraction.md，不要在两处分别维护：

node scripts/analyze-lexicon.mjs <文本文件或目录> [输出 JSON] --sample-size 120 --sample-seed 42 --sample-strategy random --min-paragraph-chars 20

第一轮固定种子抽取 100–300 个有效段落，人工发现候选词后用同一词表复扫样本，再以 --sample-size 0 完成全文验证。所有原文样本保存在私人层；公开档案只保存匿名统计和可复核结论。

2. 识别文风

文风不是“多用高级词”或“句子写得长”。它是同一说话者、作者、团队或文体长期稳定的选择：用什么词进入问题，句子怎样施加动作，段落怎样展开，整篇先让读者知道什么，以及这些选择在什么场景下改变。

先记录可观察证据，再推定阅读效果：

层级 要记录什么
词汇 人称、称呼、判断依据、确定程度、行动词、评价词、回应词、句首句末、语域、稳定搭配和禁用词
句式 言语行为、主语与责任、主动或被动、焦点位置、否定方式、逻辑骨架、句长、断句和重复
段落 段首功能、主要展开方式、段尾功能、常用骨架、拆段条件、过渡和列表使用方式
整篇编排 读者首要问题、答案位置、背景深度、证据与反例顺序、常用全文路线和结尾合同

再分开记录关系、判断与行动、情绪、信息和节奏等阅读效果。每项写清证据、可能的混淆因素、适用性和置信度；没有证据时标为“不适用”或“证据不足”，不能补造特征。

3. 建立和迁移文风

只有同一文体、相近受众和相近目的的样本，才可放进同一文风比较组。不要把考场议论文的宏大抒情、文学散文的意象、技术说明的准确克制混成一种“高级文风”。

需要从样本文本提取文风，或让某种文风实际约束 Codex 的本次输出时，先生成逐类词汇统计和 LexicalProfile，再完整读取 references/nonlexical-style-extraction.md 与 references/style-extraction.md，生成非词汇档案、完整 StyleExtractionReport 和供实际写作使用的最终 StyleProfile。所有档案都沿用语料语言，并直接采用目标风格书写。

每个稳定维度记录一个主倾向、一个确有证据的次倾向，以及触发变化的场景。声音一致不等于每句话相同；普通场景与高风险场景可以使用不同强度，但变化必须发生在可预测的范围内。绑定时先让语料实际偏好的词、搭配、句首句末习惯和确定程度进入用户可见输出，再处理句式、段落、整篇编排、声音和表现策略；代码、标识符、日志、引用、事实和责任主体不因文风而改变。

完成验证后再命名和生成 Skill。正式名称、五份档案、HTML 阅读版、规则字段、来源隔离、运行时加载和七项验证的唯一规范见 references/style-extraction.md，本页不再复制这些字段。

创建新语言风格 Skill 时，先运行使用 skill-creator 的初始化脚本封装：

node scripts/init-language-style-skill.mjs <skill-name> --path <输出目录> --display-name <正式名称> --language <zh|en> --description <触发说明>

完成提取、替换所有占位内容并生成界面 metadata 后，必须从当前正式档案同步生成 references/style-guide.html。HTML 使用目标语料语言和目标文风，集中展示五份档案、证据报告及已有任务适配器，并提供目录、搜索、折叠、明暗切换和打印；它是面向用户的主要查看入口，只供人阅读，不是新的规则事实源，也不参与 Agent 的普通运行时加载：

node scripts/render-language-style-html.mjs <目标 Skill 目录>

向用户交付或现场查看时，必须用系统浏览器打开 HTML，不能用 Codex 的源码查看器或文件预览代替；文件预览通常不会执行搜索、折叠、主题切换等页面脚本。可以直接双击 style-guide.html，或运行：

node scripts/render-language-style-html.mjs <目标 Skill 目录> --open

普通用户默认只需要 HTML。Markdown 和 JSON 供 Agent 加载、规则复核和数据审计使用；除非用户要求查看原始档案，不要把一组 Markdown 文件当作主要交付入口。具体风格 HTML 默认认为读者已经理解本 Skill 定义的四层通用规范，只展示该风格的实际词汇、句式、段落、整篇参数和验证结果；不要在每个页面复制通用方法。页面顶部必须提供返回 clear-science-writing 的通用规范链接。

词汇层必须由 references/four-layer-type-catalog.json 的8个大类、193种通用词汇类型与 style-data.json 中的目标统计联合生成数据驱动字典，不能再把词汇总表写死在 HTML。只自动映射同名唯一类型；通用类型把旧类别拆得更细时，不根据词条重合强行拆分目标统计，而是保留目标扩展。目标字典保存实际命中次数大于零的目标参数；零命中类型仍留在通用候选库和检查报告中，不进入具体语言风格 Skill。面向人的具体风格 HTML 只显示覆盖率不低于 1% 的参数，低于 1% 的统计仍保留在 JSON 中供复核。具体风格页面只保留“按类型归组”和“具体词条”两种查看方式；两种视图都使用默认展开的等尺寸卡片，并在卡片标题区显示命中次数与覆盖率，不提供搜索、筛选、排序、展开收起或复制操作。完整搜索和字典维护功能只属于通用规范页。类型数、类型内词条数、去重词条数和多重归类词数必须由当前数据实时计算。词条的通用定义、作用和注意项与目标语料的次数、覆盖、位置、组合、变化和对照属于不同字段；页面可以联合展示，但不能用通用分类说明伪造目标语料统计。生成 HTML 时同时生成 references/vocabulary-dictionary.json，并确保它与 HTML 内嵌数据一致。下载当前 HTML 时，应把用户已经应用的词汇数据重新嵌入下载文件。

句式层必须同时加载 references/sentence-style-catalog.json 的通用分类轴、句式类型和具体模板，并把 style-data.json 中已有的目标语料统计映射进去。完整字典维护界面提供搜索、分类筛选、排序、编辑、导入和导出 JSON；具体风格 HTML 只保留“按句式类型”和“按具体模板”两个卡片视图，默认显示具体模板，隐藏覆盖率低于 1% 的卡片。生成 HTML 时同时生成 references/sentence-dictionary.json，并确保它与 HTML 内嵌数据一致。通用字典中的分类轴、句式类型和模板只规定检查范围；未映射不得显示为零次，实际计数为零的目标项也不得保存到具体风格 Skill。目标语料出现而通用库尚无唯一对应的句式，保留在“目标文风扩展”中，不得丢弃或强行错配。

段落层和整篇层使用 references/four-layer-type-catalog.json 中的分类轴、类型和具体模板。段落层生成 references/paragraph-dictionary.json，至少包含8个分类轴、112种类型和65个通用模板；整篇层生成 references/composition-dictionary.json，至少包含9个分类轴、118种类型和60个通用模板。完整字典维护界面保留搜索、分类筛选、类型跳转和 JSON 操作；具体风格 HTML 只保留类型视图与具体结构视图，默认显示具体结构，隐藏覆盖率低于 1% 的卡片。无法唯一对应的目标段落或整篇结构进入目标扩展，不得按零次处理。

字典随提取任务持续更新，不冻结在首次生成版本。每次 style-data.json 改变后重新生成目标词汇和句式字典；新发现的词或句式先进入目标扩展并保留来源、统计和验证状态。只有同一参数在多份独立语料中重复出现、边界清楚并完成人工语义复核后，才可用 scripts/import-sentence-style-catalog.mjs 或同等受控流程升级通用候选字典。单一作品、人物或任务中的偶然写法不得直接污染所有风格的通用分类。

日常使用可以为后续迭代提供样本，但不能让 Skill 用自己的生成文本证明自己的规则。样本按来源分级：目标原文是来源证据；用户亲自改写的版本和用户明确接受的版本是适配证据；用户否决的版本是反向证据；未经用户确认的模型输出只能进入候选队列。日常任务不得静默改写全局 Skill；只有用户要求更新，或进入明确的维护任务时，才把最小必要记录写入 references/style-learning-log.jsonl，再重新统计、抽样复核并更新 style-data.json。不要保存无关对话、私人内容或整份任务历史，优先保存文本哈希、受控本地引用、差异摘要和候选参数。

新一轮语料分析完成后运行：

node scripts/update-language-style-dictionaries.mjs <目标语言风格 Skill 目录>

语料命中和对照统计完成后，使用统一权重脚本补充各层参数优先级：

node scripts/update-language-style-weights.mjs <目标语言风格 Skill 目录>/references/style-data.json

权重只用于同层排序。它由覆盖率、对照差异和复核置信度计算，不能覆盖语义适用条件，也不能把低频但必要的安全、事实或责任规则降级。

该命令重新生成 HTML、词汇、句式、段落、整篇字典和 dictionary-update-report.json。如果存在 references/style-learning-log.jsonl，报告还会区分可复核样本、反向样本、模型候选和待人工判断的参数。报告逐层列出目标参数规模、映射结果、歧义项、未映射项和通用字典升级候选。它只负责发现维护工作，不自动修改正式统计，也不自动把目标扩展升级为通用参数。学习记录格式见 references/style-learning-log-schema.json。

面向人的 HTML 必须按“先看整体 → 第一层词汇 → 第二层句式 → 第三层段落 → 第四层整篇编排 → 综合使用 → 复核”逐层递进，不能按 Markdown 文件名排列。四层采用同一展示合同，不能词汇层有词典和数据，句式、段落、整篇却只剩几条概括。每一层都依次展示：主要特征、具体类型或结构、常见组合、场景变化、正反样例、数据与文本依据、置信度和未验证项。

生成和校验四层档案时，完整读取 references/four-layer-writing-contract.md、references/four-layer-style-data-schema.md、references/four-layer-feature-catalog.json 与 references/four-layer-type-catalog.json。严格继承其中的客观分析维度、候选字典和数据合同，不把参考材料中的任何候选写法直接当成目标技巧。候选库只规定必须检查的范围，不能冒充目标风格；候选句式、段落序列和内容路线必须保留名称、模板或序列及客观关系，便于逐项统计。所有维度都必须检查并在候选库、审计字段或独立报告中留下状态；目标档案只列语料实际命中的参数：词汇列实际词，句式列“……吗”“不是 A，而是 B”一类实际结构，段落列实际动作序列，整篇列实际信息路线。四层每个实际命中的参数统一记录类型、频率、位置、组合和变化范围，并写入 references/style-data.json；次数为零的参数不得写入目标 Skill。缺少其中任何一项时只能算部分完成。候选表里的例词、反问、排比、段落模板或“答案先行”等写法，没有语料证据时不得进入目标 StyleProfile。

新增或修订四层类型库时，保留两份重要原始参考：文风参数化方法论_四层类型字典版.html 供人阅读，文风参数库_四层类型字典.json 供数据复核。运行时使用由下列命令增量合并生成的 four-layer-type-catalog.json，不要直接改写原始参考：

node scripts/import-four-layer-style-catalog.mjs references/文风参数库_四层类型字典.json

递进只负责阅读顺序，不得隐藏证据。每层结论后面都要就近提供可展开的依据，至少说明可观察事实、样本和全文范围、频率或结构指标、对照差异、混淆因素、规则状态、验证结果，以及当前证据不能推出什么。证据不足时保留该层和相应类型，但标为候选、暂定或未验证；不能为了填满四层而补造稳定特征，也不能直接从词频跨层推断句式、段落或整篇结构。

给人阅读的通用规范使用 references/language-style-standard.html。本 Skill 或词汇、非词汇、风格提取规范改变后，重新生成它：

node scripts/render-language-style-standard-html.mjs <clear-science-writing Skill 目录>

随后同时运行系统基础校验和专用合规校验：

python -X utf8 <skill-creator>/scripts/quick_validate.py <目标 Skill 目录>
node scripts/validate-language-style-skill.mjs <目标 Skill 目录> [--forbid-source <来源名称>]
node scripts/validate-language-style-skill.mjs <目标 Skill 目录> --require-complete [--forbid-source <来源名称>]

完整度不得由报告自报。style-data.json 中仍有未统计、证据不足，或只由宽松规则得到且未完成人工语义复核的参数时，对应层必须失败；段落与整篇还必须有人工复核证据。

第一条检查文件、字段、链接、同步状态、运行时规则和来源隔离是否正确；第二条再检查词汇、句式、段落和整篇编排是否都达到“完整”成熟度。--require-complete 不只读取报告中的状态，还会独立核对各层档案是否有规定参数、正向单位数、对照证据、可执行来源规则和通过验证的 observation；段落与整篇还必须有人工复核证据。它同时校验正文文风记录：除标题、表格及表格数据、代码、JSON、导航和控件外，目标 SKILL.md、五份正式档案、已有任务适配器和 HTML 正文必须使用目标语料语言，并由独立任务按词汇、句式、段落和整篇四层复核；正文或 HTML 改动后，哈希不一致会使旧记录失效。最终交付目标语言风格必须通过该检查。如果某层只有候选、任务适配器或由其他层间接推断，结构校验可以通过，但成熟度只能是 partial 或 insufficient，不得称为已经完成的语言风格。

style-extraction-report.json 必须包含 layerMaturity 和 bodyStyleValidation。四层分别记录分析单位、单位数、已完成检查、仍缺检查和证据说明；overall 由四层状态自动核对。bodyStyleValidation 保存被复核正文的版本、语言、源文件哈希、Markdown 与 HTML 正文哈希、逐文件结果和独立复核记录。词汇层的词频不能替代句式统计，对白碎片不能替代段落边界，局部发言不能替代整篇编排；规则表完整也不能替代正文实际采用目标文风。校验器必须把“文件齐全”“证据齐全”和“正文文风通过”分开报告。

改写时先保留目标文本的身份和任务，再选择两三项可迁移的文风特征，例如“短句为主 + 具体动词 + 先事实后判断”。不要逐句仿写，也不要为了模仿词频而牺牲事实边界。

4. 用修辞控制语气和节奏

  • 对比：比较对象处在同一维度，并写出差异造成的结果。
  • 比喻或类比：说明陌生机制与熟悉经验的对应关系；必要时说明类比在哪一点失效。
  • 排比：并列项的语法和层级一致；过长时改为列表。
  • 设问：提出读者真正会问的问题，紧接真实回答。
  • 反复：固定主旨、术语或限制，不用近义词轮换制造文采。
  • 举例：把抽象机制落到具体场景，不以个例冒充普遍结论。

避免用口号、连续反问、堆叠形容词、过度拟人或戏剧化语气制造“力度”。它们不能弥补缺失的因果和证据。

词汇层的 HTML 只从统一词汇数据生成，不维护第二份手写词表。生成器同时输出 vocabulary-dictionary.json，供复核、导入和其他工具读取；该文件必须与 HTML 内嵌数据一致。字典把两类信息分开保存：

  • 通用分类信息：大类、类型名称、定义、作用、使用场景、注意项、信号和核心／扩展标记；
  • 目标语料信息：实际词形、次数、标准化频率、覆盖、位置、组合、变化、对照和验证状态。

一个词可以进入多个类型。词条索引应按词形合并类型关系，但不能把不同类型中的次数或功能强行归并成单一语义。页面统计数字由当前 JSON 自动计算，并支持类型浏览、词条反查、多重归类筛选、数据编辑和 JSON 导入导出。修改通用分类不会自动产生目标语料计数；缺少统计的新增类型仍应明确显示为未测量。

人类阅读版的数据驱动句式字典

句式层先回答“一句话客观上属于哪些类型”，再回答“它使用了哪个具体模板”。通用字典因此分成分类轴、句式类型和具体模板。目标语料统计另行保存并映射到模板；类型统计只能由已映射模板汇总，不能把通用类型数量当成目标频率。

目标语料中的新句式若尚未与通用模板建立唯一对应，必须保留为目标文风扩展。随着新语料进入，目标字典可以不断增加；升级通用字典则需要跨语料复现、人工确认边界和可复核的识别条件。

人类阅读版的数据驱动段落与整篇字典

段落层与整篇层采用和句式层相同的双层结构：先按多个客观分类轴判断类型，再查看完整的句子功能序列或全文模块序列。段落通用目录包含8个分类轴、112种类型和65个模板；整篇通用目录包含9个分类轴、118种类型和60个模板。

通用类型和模板只回答“检查什么”。目标语料的次数、位置、组合、变化和验证状态单独映射。自动功能标签与通用模板无法唯一对应时，保留为目标扩展；人工标注完成前不能强行归类，也不能把未映射解释为未出现。

日常样本与持续更新

日常写作产生的反馈可以补充目标风格，但进入正式统计前必须经过来源判断：

  • source_corpus：目标原文，可以参与来源规律统计；
  • user_revision：用户亲自修改后的文本，可以参与任务适配统计；
  • user_accepted：用户明确接受的生成文本，可以作为适配样本，不能反推原作品规律；
  • user_rejected：用户明确否决的文本，只作为反向样本；
  • model_candidate：未经确认的模型输出，只能提出候选，不计入正式频率。

维护任务将最小必要记录写入 style-learning-log.jsonl。记录至少包含样本 ID、时间、语言、来源类型、决定、文本哈希或受控本地引用、涉及层级、候选参数和复核状态。更新时先去重，再分别统计来源语料和适配语料；两者不得合并成一个频率。用户没有要求维护 Skill 时，普通写作任务不得静默写入该日志。

词汇是第一风格约束。人称、情态、程度、评价、语气词和句首句末习惯一旦改变，即使事实与句式不变，读者感受到的身份、距离和态度也会改变。

两遍提取

第一遍按分类词表搜索，回答每个类别中实际出现了什么。第二遍做开放发现，寻找分类表没有预设但在语料中反复出现的词、短语、句首、句末和固定组合。

如果只做第一遍，结果会被参考词表限制，语料中真正稳定的说法可能被漏掉。如果只做第二遍，高频题材词又会淹没人称、情态和语气词。因此两遍都必须完成。

统计方法

语料较大时先运行：

node scripts/analyze-lexicon.mjs <文本文件或目录> sample-report.json --sample-size 120 --sample-seed 42 --sample-strategy random --min-paragraph-chars 20

脚本接受 .txt、.md 和 .jsonl，根据全部有效正文判断中文或英文，输出分类计数、每万字符或词的标准化频率、文档与段落覆盖、句首句末和段首段尾位置、左右搭配候选、开放词汇候选、词类组合和基础非词汇指标。句长变化只在同一段内部计算，词类共现也不会被直接解释成言语行为。Markdown 的围栏代码、行内代码、链接目标和裸 URL 不进入词频、句长、逻辑词或开放词汇统计；链接文字和去掉列表、引用、标题标记后的正文仍保留。普通正文软换行、连续引用行和列表续行会合并为一个分析段落，新的列表项与嵌套列表项仍各自成段。corpus.sourceRecords 记录解析器看见的正文与排除记录总数，corpus.sourceParagraphs 只记录可分析的真实段落，不能混用。.txt 与 .md 以文件为文档，.jsonl 以每条含文本记录为文档；JSONL 依次读取 quote、text、content、paragraphText 中第一个非空字符串，并在 corpus.jsonlDiagnostics 报告跳过或按原文使用的异常行。文件覆盖、段落覆盖和说话场景覆盖不能混写。混合语料仍须先按语言分组，不能把自动判断当成分组。默认不保存原文句子；只有显式使用 --sample-output 时才写出本地样本。报告默认把文件来源匿名化，不写本机绝对路径。任何统计都不能替代上下文判断。

LexiconScanReport 当前为 Schema v3。v3 新增 sourceRecords、段落层指标、词类组合与 pathMode，并把默认来源字段改成匿名标签；读取旧 v2 报告或维护下游脚本时，必须按版本分支处理，不能假定 corpus.input、corpus.files 和 paragraphReferences.file 一定是可访问路径。

推荐流程：

  1. 用 --sample-size 100 到 300 做初次随机样本，固定 --sample-seed。
  2. 如果材料跨多个文件或前后差异明显，改用 --sample-strategy stratified。样本数不少于有效文档数时，脚本先保证每个文档至少一段，再把剩余名额分配到全文位置。
  3. 需要阅读原段落时使用 --sample-output <private-sample.jsonl>；把它保存在输入语料目录之外，不要提交到仓库或公开 Skill。脚本会跳过自己生成且带标记的样本文件，但历史导出文件仍需人工隔离。
  4. 默认保留 --path-mode anonymous。私人复核若需要识别来源文件，使用 --path-mode relative；--path-mode absolute 只用于本机排障，生成的报告不能公开或写入可分发 Skill。
  5. 从样本中发现分类表未覆盖的词与短语，保存为 JSON，例如 { "自定义判断词": ["倾向于", "更可能"] }。
  6. 用 --terms-file <词表.json> 重新执行；--terms-mode merge 合并内置分类，only 只统计自定义词表。
  7. 样本结论稳定后，再用 --sample-size 0 扫描全部非空段落，验证频率和分布是否仍然成立；如果仍需排除短行，再显式传入 --min-paragraph-chars。

--sample-size 只限制进入统计和人工样本的段落数。脚本仍须先读取、解码并切分全部输入，以便判断语言和建立抽样总体，因此它不是内存限制。超大单文件或大量 JSONL 记录应先在私人目录按语言、章节、场景或来源拆分，再分批运行并保存各批分母；不能把几批覆盖率直接相加当成全局覆盖率。

还可以使用 --min-paragraph-chars 排除过短正文，使用 --open-top 控制开放词汇候选数量，使用 --min-count 隐藏低于指定次数的参考词。被隐藏但实际出现的词进入 belowMinimumForms，不会混入 absentReferenceForms。

类别可以重叠，短语也可能包含单词，例如“这是什么”会同时命中短语和“什么”。因此分类总数不能相加当作唯一词数；它们只用于比较同一类别中的偏好。词类组合要求同一句或同一段至少出现两个不同词形；“可能”同时属于“确定程度”和“缓和”时，单独一个“可能”不会生成这两个类别的组合。即使出现了两个不同词形，共现仍不是言语行为结论，必须回看上下文。中文单字只把分词器识别出的独立单字记入确认次数；“不走、我去、别人、去年、没收”中的单字子串都进入 ambiguousReferenceForms，不会自动算成对应功能词，也不能写成“未出现”。Agent 必须回看上下文，再决定是否把候选加入自定义短语或人工结论。

不要只输出词频表。每个候选词或短语至少记录：

词或短语：
功能类别：
总次数与标准化频率：
覆盖了多少篇、章节或说话场景：
覆盖了多少段和多少句：
常见搭配：
常见位置：句首／句中／转折／结尾／单独成句
实际作用：提问／保留／强调／否定／评价／行动等
可能混淆的其他作用：
对照组差异：
是否可迁移：

中文同时统计单词、二至六字短语和句末组合。例如“什么”“这是啥”“这是什么”“什么意思”不能只合并成一个“疑问词”数字。英文需要统计词形变化、缩写、情态动词、短语动词和句末附加问句。

频率必须标准化，例如每万字、每千词或每百段出现次数。再检查分布：一个词出现一百次但集中在单章，不如一个词在二十篇材料中都稳定出现更能说明文风。

一本书或一份长记录若只放在单个 .txt 文件中，文档覆盖率几乎只能是零或一。此时优先查看脚本新增的段落覆盖率，并在私人预处理层把章节、说话场景或文章拆成独立 JSONL 记录，再把记录覆盖解释为对应逻辑单元覆盖。报告必须写清覆盖分母究竟是文件、记录、段落、章节还是场景，不能互换名称。

逐类回答“主要用什么”

每个词类都要生成一条实际分析，不允许只复制分类说明：

类别：疑问词与疑问短语
语料实际出现：什么 42、怎么 18、为什么 9、啥 0、何种 0
主要偏好：以“什么、怎么”为主，不使用“啥”，书面疑问“何种”也未出现
位置：多数位于直接问句中；少量“什么”出现在反问句
稳定组合：这是什么、什么意思、怎么可能
作用：索取信息为主，反问为辅
覆盖：分布于 11/14 个样本，不是单篇集中
置信度：较高

数字只是格式示例，不能写入其他语料的结果。没有对应词时写“未观察到”，不要从参考表补一个看起来合理的答案。

同义词必须放在同一组比较。例如：

  • 什么／啥／何种；
  • 怎么／咋／如何；
  • 为什么／为啥／缘何；
  • 但是／不过／然而；
  • 应该／必须／建议／可以；
  • 很／挺／非常／极其；
  • 其实／问题是／严格来说；
  • 吧／呢／啊／啦／哦。

文风往往来自“选择了哪个，没有选择哪个”。因此零次出现也可能有意义，但只有语料规模足以支持时才能解释。

感叹、拟声与停顿词 哈哈、哎、啧、唉、嗯、呃 即时情绪、迟疑和真人感
回应与确认词 嗯、哦、好、行、明白、收到、知道了 对话温度、承诺程度和是否给出后续动作
语域词 啥／什么／何种，咋办／怎么办／应如何处理 口语、中性、正式或古典程度
网络、方言和圈层词 离谱、稳了、整、搞、这玩意 年龄感、地域感和群体身份
外来语与缩略语 OK、NG、UI、KPI、deadline 行业、代际、跨文化语感和读者门槛
专业术语 架构、耦合、留存率、帧同步 专业身份和读者门槛
带评价的名词与动词 砍掉、阉割、塞、拍脑袋、鸡肋 不通过形容词也能表达褒贬和攻击性

类别不是固定词典。“可能”主要表示确定程度，不应因为常出现在条件句里就统一算作条件词；“别”是禁止词；“直接”通常描述行动方式；“可以”要根据上下文区分许可、能力和可能性；“应该”要区分义务、建议和推断；“其实”可能是修正词，也可能只是无意义起手词。

礼貌程度、行动压力和判断确定性必须分开标注。“请务必停止”很礼貌，但仍是强制要求；“我不确定原因，但必须先停机”判断保留，却不降低行动压力。不要把它们压成一个“语气强弱”数字。

句首、句末与组合

单词频率不足以解释个人风格，还要统计位置：

  • 句首：其实、问题是、简单说、说白了、严格来说、老实说、首先、那么、你看；
  • 句末：吧、呢、啊、啦、呗、哦、哈、对吧、是不是；
  • 否定组合：并不是……而是、不能说……只能说、不是因为……而是因为；
  • 条件组合：如果……那么、只要……就、除非……否则；
  • 不确定组合：可能是……也可能是、目前更倾向于、还不能排除；
  • 决策组合：应该先……再、必须在……之前、可以……但是；
  • 重复组合：真的很、不是……不是、不能……不能。

句首词决定说话者怎样进入问题，句末词决定他怎样退出一句话。两者通常比正文中的主题名词更容易形成稳定辨识度。

多类词怎样共同出现

单个词只能说明一个局部选择，稳定声音通常来自多类词在同一句或同一段中的组合。至少检查：

  • 人称或称呼 + 确定程度 + 行动词；
  • 判断依据 + 因果或修正词 + 范围限定；
  • 程度词 + 评价词 + 句末语气词；
  • 请求或礼貌词 + 命令或禁止词；
  • 句首进入方式 + 句末退出方式；
  • 口语、书面、专业、方言和缩略语是否处在同一语域。

报告组合时记录共同出现的句数、段数、覆盖率和相对独立出现的比例。组合类别可能重叠，不能把共现直接解释为因果；它只说明哪些选择经常一起出现。再回看原句，判断组合实际形成的是协商、说明、试探、命令、吐槽还是别的言语行为。

需要检验某个词是否真的造成某种阅读效果时，制作单变量对照：保持事实、句法和上下文不变，只替换该词或句尾，再检查效果是否随之变化。如果必须同时改动人称、句长和段落顺序，不能把变化只归因于这个词。

开放发现

分类表之外继续检查：

  • 高频实词：最常使用的动作词、评价词、抽象名词和具体名词；
  • 二至六词或二至十二字的高频组合；
  • 重复出现的句首三至八字和句末二至六字；
  • 某个词前后最常共现的词；
  • 只在目标作者、说话者、团队或文体中明显偏高的词；
  • 高频但只属于主题、情节、产品或行业的词。

开放发现得到的词仍要回到上下文判断功能。不能因为“系统”出现最多，就把文风命名为“系统式”；也不能因为某个说话者总在特定场景里说“计划”，就直接认定所有输出都应反复使用“计划”。

区分来源词与内容词

将候选词分为四层：

  1. 稳定来源词：跨主题、跨位置、跨样本承担相同作用。
  2. 低频来源词：有特征，但证据不足，只在匹配情境中使用。
  3. 内容与题材词：人物名、产品名、世界观、事件对象和行业对象，不作为通用风格迁移。
  4. 任务工作词：目标任务必须保留的术语、风险词和责任词，可以使用，但不冒充来源风格。

词频高不等于可迁移。只有位置、搭配、功能和跨样本分布同时稳定，才能写入来源词汇档案。

第二层 · 句式

分析词语怎样组成言语行为、主语与责任、焦点、条件因果、否定、问句、命令、句长和标点。

句式分类轴与具体模板

句式层包含 9 个分类轴、129 种类型和 286 个具体模板。同一句可以同时命中多个分类轴；未建立目标统计映射时不能显示为零次。

  • 句子用途（句类）：按句子的表面用途分类：陈述信息、提出问题、要求行动或表达感叹。
  • 结构层级与完整度：记录句子由一个还是多个分句组成，以及成分是否完整、省略或片段化。
  • 主干骨架：按主语、谓语、宾语、补语以及“把、被、有”等结构标记分类。
  • 疑问形式：按问句要求的答案形式和固定标记分类。
  • 要求、请求与回应形式：按句子直接完成的交际动作分类，例如命令、请求、建议、拒绝和确认。
  • 分句逻辑关系：记录两个或多个分句之间的因果、条件、转折、并列、选择等关系。
  • 信息顺序与重点：记录结论、原因、条件、时间、地点、对象、来源等信息放在句子的什么位置。
  • 叙事、描写与引语：记录动作、感知、想法、环境、对白和情绪怎样组合成句。
  • 修辞、重复与节奏：记录比喻、拟人、排比、反复，以及长短句、停顿和重复位置。

第二层：句式维度

分析词汇怎样组成一句话。至少检查：

  • 句类分布；
  • 言语行为分布；
  • 主语类型；
  • 主语出现、省略与恢复；
  • 责任主体的明确程度；
  • 主动、被动、状态和无人称表达的分布；
  • 视角与判断归属；
  • 语序；
  • 话题和焦点位置；
  • 句首与句尾的信息落点；
  • 插入信息的位置与形式；
  • 肯定方式；
  • 否定方式；
  • 限定方式；
  • 纠正方式；
  • 逻辑关系类型及其显化程度；
  • 关系组合数量和层级；
  • 简单句、并列句、主从句和省略句的分布；
  • 分句数、嵌套深度、指代负担和关系链长度；
  • 句长分布与离散程度；
  • 相邻句长变化和长短组合；
  • 完整句、碎片句和故意断裂的分布；
  • 重复方式；
  • 平行与递进方式；
  • 标点分布；
  • 断句位置与语义边界；
  • 不同场景下句式参数怎样变化。

句式档案必须建立完整候选模板库，并分别回答这些维度的实际取值、功能和证据。每种句式至少记录名称、模板、语法或逻辑关系、识别标记、每百句次数、覆盖率、位置、组合、变化范围、对照差异和验证状态。不能把词频当作句法证据，也不能把候选模板直接当作目标风格。

句式参数必须尽量写成可识别形式，例如抽象槽位、标记词、语序关系或标点结构。只写“偏理性、逻辑较强、常用转折”不算参数。

句式档案

句法和焦点

至少检查：

  • 主语是否出现；出现时放在句首、句中还是判断之后；
  • 责任主体是否清楚，还是被无主句、被动句或抽象名词隐藏；
  • 主动、被动、判断、定义、把字、祈使、省略和碎片句怎样分布；
  • 条件、时间、风险、对象、原因或结论是否经常提前；
  • 重点落在句首、句尾、插入语、括号、破折号还是独立短句；
  • 并列、从属、让步、因果、比较和纠正结构怎样组合；
  • 完整句与省略句分别在什么场景出现。

不要用“短句就是口语、长句就是专业、被动句就是正式”这类固定映射。相同句长可以承担命令、结论、笑点或文学停顿，必须记录功能。

言语行为与关系

句式还要回答“这句话正在做什么”。标注：

  • 告知、询问、确认、建议、请求、要求、禁止、拒绝、承诺、道歉、安抚或邀请行动；
  • 开放疑问、一般疑问、选择问、确认问和反问；
  • 直接说出意图，还是理由前置、暗示、让步后转向或通过反问施压；
  • 是否解释原因，是否给对方选择，是否写出安全替代；
  • 如何处理异议：承认一部分、重设范围、给证据、否定、回避或攻击；
  • 高风险或不可逆场景中，行动压力怎样升级。

礼貌、判断确定性和行动压力是三个轴。“请务必停止”有礼貌但行动压力很高；“原因还不能确定，但必须先停机”判断保留却仍是明确命令。

长度、节奏和停顿

报告平均句长之外，还要给出中位数、P75、P90、标准差或变异程度，并在段落内部观察相邻句长变化。检查：

  • 连续短句通常承担结论、命令、紧张、反转还是笑点；
  • 长句承担条件链、背景、机制还是情绪累积；
  • 是否存在稳定的“长分析—短结论”“短行动—长解释”或其他交替；
  • 逗号、句号、分号、省略号、破折号和括号怎样分配停顿；
  • 重复、平行和故意断裂是在强调、安抚、推进还是制造反差。

第三层 · 段落结构

分析段首怎样进入、中段怎样展开、段尾怎样退出，以及骨架、拆段、过渡和列表的稳定选择。

段落分类轴与具体模板

段落层包含 8 个分类轴、112 种类型和 65 个具体模板。类型用于多轴分类，模板记录完整的句子功能序列。

  • 段落主要任务：记录一个段落在局部主要完成什么任务，例如定义、分析、叙事、说明步骤或完成一轮对话。
  • 内容展开关系：记录段内信息怎样展开，例如定义—例子、原因—结果、问题—解决、证据—结论。
  • 中心信息位置：记录本段最主要的判断、答案、结果或行动安排位于段首、段中还是段尾。
  • 句子连接方式：记录句子之间采用链式、并列、总分、分总、对照、分支或轮次等连接方式。
  • 时间与空间顺序：记录叙事或描写是否按时间、回忆、场景切换、并行人物线或空间方位组织。
  • 段首功能：记录段落第一句承担的功能，例如定义、观点、问题、背景、动作、对白或规则。
  • 段尾功能：记录段落最后一句承担的功能，例如结论、结果、感受、解决办法、例外、确认或转场。
  • 表面组织形式：记录段落在页面或对话中的可见组织形式，例如连续正文、列表、问答、对话轮次、步骤或条件分支。

第三层：段落维度

分析若干句子怎样完成一个局部任务。至少检查：

  • 段落的中心任务；
  • 段首功能；
  • 中段展开功能；
  • 段尾功能；
  • 段内动作序列；
  • 主干信息与辅助信息的关系；
  • 事实、判断、原因、证据、例子、条件、反例、步骤和行动在段内的位置；
  • 段落长度分布；
  • 单句段与多句段的比例和功能；
  • 拆段触发条件；
  • 合段条件；
  • 相邻段落的承接方式；
  • 过渡的显式程度；
  • 自然段、列表、表格、引用和提示块各自承担的功能；
  • 不同场景下段落参数怎样变化。

段落层必须建立句子功能序列候选库，例如“问题 → 原因 → 解决办法”这一类可检查结构；它只规定检查范围，不规定目标语料必然采用。目标段落骨架必须从完整段落的人工标注中归纳，不得用单句对白或自动功能标签替代人工边界判断。

段落档案

段落是一个主要任务加完成该任务所需的辅助材料，不是固定三句模板。逐段标注：

  1. 段首怎样进入：结论、问题、事实、场景、定义或承接前文；
  2. 中间怎样展开：原因、证据、例子、步骤、对比、分类、条件、反例或回应异议；
  3. 段尾怎样退出：小结、判断、行动、限制、悬念或转向；
  4. 整体骨架：例如结论—原因—行动、观点—解释—例子、问题—原因—方案、事实—影响—判断、场景—变化—含义；
  5. 怎样拆段：按话题、行动阶段、时间、说话者、场景或重点变化；
  6. 怎样过渡：依靠内容复现、因果、对比或问题承接，还是机械插入“首先、其次、总之”；
  7. 怎样排版：自然段、单句段、列表、表格、引用和提示框分别承担什么关系。

每段只统计长度还不够。要说明段首、展开和段尾各自做了什么，以及这种骨架是否跨样本重复。列表只能证明信息被分行，不能自动证明逻辑清楚。

第四层 · 整篇编排

分析答案、背景、证据、反例、分支、行动和结尾在全文中的位置与顺序。

内容编排分类轴与具体模板

整篇层包含 9 个分类轴、118 种类型和 60 个具体模板。类型用于说明整篇怎样编排，模板记录完整模块顺序。

  • 整篇主要任务：记录全文主要要完成什么任务，例如叙述事件、解释知识、分析问题、指导操作或组织游戏文本。
  • 主要编排顺序：记录模块主要按时间、空间、分类、因果、问题、证据、步骤、线索或分支排列。
  • 开篇模块：记录全文最先公开什么，例如结论、背景、问题、定义、目标、触发条件或数据范围。
  • 主体组织方式：记录正文是线性推进、并列分节、层级树、问答单元、步骤序列、证据链、时间线还是分支树。
  • 结尾模块：记录全文最后用结果、感受、结论、决定、下一步、反馈入口、揭示或关联条目收束。
  • 信息公开方式：记录信息是一次公开、逐步公开、延迟揭示、按角色知识限制、按状态解锁还是按分支分别公开。
  • 阅读与交互路径：记录读者按线性顺序、目录检索、问答跳转、条件树、玩家选项或状态入口访问内容。
  • 模块重复方式：记录整篇是否重复使用同一种模块单元，例如多个问答、多个词条、多个步骤、多个标准或多个分支。
  • 信息来源与知识范围：记录全文信息来自个人经历、组织声明、数据证据、教学者、角色有限知识、系统数据库或多个来源。

第四层：整篇编排维度

分析各段怎样安排读者的理解顺序。至少检查：

  • 文本目的；
  • 主要读者；
  • 读者已有信息；
  • 读者首要问题；
  • 开头最先释放的信息类型；
  • 核心答案或判断的位置；
  • 背景的位置和深度；
  • 原因与机制的位置；
  • 证据的位置和次序；
  • 例子的位置和次序；
  • 反例、异议和限制的位置；
  • 方案、比较和选择的位置；
  • 行动、责任主体和时间的位置；
  • 成功标志、失败处理和恢复信息的位置；
  • 信息排序依据；
  • 全文推进路线；
  • 展开深度；
  • 结尾功能；
  • 媒介、用途、读者和风险变化怎样改变编排；
  • 哪些编排属于来源风格，哪些只是任务格式或文体惯例。

整篇层必须建立内容模块及其顺序候选库，记录模块类型、出现频率、常见位置、前后组合和场景变化。目标整篇路线必须从足量完整文本中归纳；候选库不预设答案先行、时间顺序、问题解决、悬念推进或任何其他路线是目标风格。

整篇编排档案

整篇编排回答读者先知道什么、后知道什么。它与内容模型不同：内容模型规定必须保留哪些事实，编排档案记录相近任务中稳定偏好的呈现顺序。

逐篇标注：

  • 文本用途、主要读者和读者打开文本后的首要问题；
  • 答案、结论、异常、场景或背景最先出现；
  • 背景放在开头、解释段、需要时插入还是附录；
  • 证据、例子、反例、限制和行动分别放在什么位置；
  • 使用答案先行、问题解决、教程流程、比较选择、观点论证、案例归纳、总分、时间顺序或悬念推进中的哪一类路线；
  • 解释下钻到结论、原因、机制、例子、边界、反例和步骤中的哪一层；
  • 结尾交付结论、行动、责任主体、成功标志、失败恢复、余味还是新问题。

只有相近文体、读者和目的的文本可以比较整篇顺序。小说的悬念后置不能直接迁移到安全说明；技术文档的答案先行也不能证明叙事文本缺少风格。

05

综合使用

四层必须共同出现，并保留阅读效果、声音指纹、场景变化和不可迁移内容。

基本规则

  1. 按词汇、句式、段落、整篇编排四层分析。阅读效果是四层共同产生的结果，不是第五层。
  2. 每个维度都必须留下状态：稳定、场景限定、暂定、否决、未观察到、不适用或证据不足。
  3. 每个成立的取值都必须记录分析单位、数量或比例、分布、位置、组合、同类对照、场景变化、混淆因素、验证结果和置信度。某项指标不适用时明确说明原因。
  4. 维度用于提出问题，不能预先给出答案。分析者不得因为参考材料列出过某种写法，就把它写成目标风格。
  5. 每层使用本层证据。词汇证据不能替代句式证据，句式证据不能替代段落证据，局部文本不能替代整篇证据。
  6. 四层统一记录类型、频率、位置、组合和变化范围。完整字段及 JSON 合同见 four-layer-style-data-schema.md。
  7. “冷静、专业、温和、强硬、成熟”等只能作为数据解释后的阅读效果，不能成为一级分类，也不能替代客观参数。
  8. 候选库和目标参数必须分离保存：候选库回答“检查过什么”，目标参数回答“语料实际用了什么”。候选项即使零次或暂时无法可靠识别，也必须在候选库、审计字段或独立检查报告中留下状态；零命中项不得写入具体语言风格 Skill 的正式参数、目标字典或正文。
  9. 每个参数统一记录五项共同属性：类型、频率、位置、组合、变化范围。词汇、句式、段落和整篇不能使用不同的完成标准。
  10. 完成度由数据反推。存在 not_measured、insufficient_evidence 或未经语义复核的自动候选时，相应层不得标为 complete。
  11. 目标风格字典允许随新语料和真实使用反馈迭代，但生成结果不能成为自证数据。目标原文、用户修订、用户明确接受、用户否决和未经确认的模型输出必须分开记录。

四层校验

使用同一组中性事实分别检查词汇、句式、段落和整篇参数。校验只改变被测试的层，其他事实和表达条件保持不变。正向样例必须由目标参数生成；反向样例要指出失真发生在哪一层。任何校准都不得引入参考材料中的固定技巧，也不得改变事实、责任、安全或审批边界。

每个效果判断写出支持证据和反证。例如“使用您”可能提高正式度，却不能单独证明温暖；短句可能加快速度，也可能形成冷淡、命令或文学停顿。需要验证单个特征时，保持事实和其他写法不变，只改变一个变量，再检查效果是否随之改变。

声音与表现策略

除四层结构外，还要检查横跨全文的选择：

  • 叙述视角和距离：谁在说、谁知道、离人物意识或读者多近；
  • 具体程度和精确程度：是否从抽象判断落到动作、物件、数字、范围和感官；
  • 信息密度和留白：单位长度有多少新信息，省略后是否仍留下推断依据；
  • 重复和修辞：关键词、句首、回环、对比、比喻、排比、反转和反讽承担什么作用；
  • 标点和排版：句号、问号、感叹号、省略号、破折号、括号、标题、列表和表格怎样组织阅读；
  • 互动与幽默：是否预判疑问、邀请行动；笑点来自反差、降格、延迟、三段式还是回调；
  • 叙事时间：顺叙、倒叙、压缩、延展、现在时或回顾怎样改变信息释放。

文学文本可以使用留白和叙事距离；工作文档通常需要降低歧义。不要把适合来源场景的省略、错误、价值立场或人物选择直接迁移到事实说明、代码和安全边界。

一致性与场景变化

声音一致不等于每句话相同。每个稳定维度记录：

  • 主倾向：最常见、跨样本稳定的选择；
  • 次倾向：真实存在但使用较少的备用方式；
  • 变化触发条件：风险、关系、媒介、情绪、文本用途或叙事阶段怎样触发变化；
  • 保持不变的组合：即使场景变化，哪些词汇关系、节奏或信息习惯仍在；
  • 禁用项：哪些词、标点、结构和情绪方式稳定缺席；
  • 不可迁移项：来源人物的价值立场、世界观、事实错误、情节选择和题材内容。

真正的声音指纹通常只需要三到五组稳定组合。孤立特征、文体默认结构、单场景爆发和题材专词不能进入核心指纹。

06

提取与验证

所有结论必须可追溯、可复算、可对照、可证伪；证据不足时保留候选，不把空位补成稳定风格。

选对样本

只把文体、读者和目的相近的完整文章放在同一组。例如，技术说明、公众科普、观点文章和文学散文应分开。每组优先收集来源、作者和用途清楚的多篇文本；网页自称“满分”或“爆款”只是标签，不是质量证明。

不整篇复制受版权保护的样本。保留链接、来源、用途和分析笔记即可。

语料过大时先固定种子抽取 100–300 个有效段落，完成词类发现和上下文判断；如果前中后段、不同文档或不同说话场景差异明显，使用分层采样。样本用于发现候选规则，全文统计用于验证规则，二者不能互相替代。

先提取词汇

完整读取 lexical-extraction.md，先完成逐类词汇统计，再生成 LexicalProfile。分类表只是搜索参考；输出必须具体说明实际语料在每一类主要使用什么、较少使用什么、常放在哪里、怎样搭配，以及哪些类别没有观察到稳定词汇。

词频之外还要记录标准化频率、样本覆盖率、位置、搭配、功能、同义替代比例和对照组差异。再做一次开放词汇发现，寻找参考分类没有预设的高频短语与句首句末习惯。词汇在特定主题中集中出现，只能说明内容；它在多个主题中持续承担同一种作用，才可能说明文风。

从样本提取文风卡

先完整读取 nonlexical-style-extraction.md，生成 NonLexicalStyleProfile，再压缩为最终 StyleProfile。

逐篇标注，再找跨文本重复出现的选择。先按词汇、句式、段落和整篇编排记录证据；关系、确定、情绪、速度等阅读效果放在第二层判断：

维度 提取问题
词汇选择 哪些词、搭配、句首、句末和禁用项跨样本稳定；它们承担什么功能？
句式构造 句子在告知、询问、建议、要求还是拒绝；主语、责任、焦点、逻辑和节奏怎样处理？
段落结构 段首怎样进入，中间怎样展开，段尾怎样退出；哪些骨架持续出现？

最终档案只保留能执行、能检查的稳定结论。每个维度优先写一个主倾向和一个确有证据的次倾向，不把几十个维度都写成硬性配额。正反样例必须根据档案重新生成，只用于校准规则，不从受保护语料复制句子。

语言风格 Skill 的正式档案规范

建立五份档案前，完整读取 four-layer-writing-contract.md 和 four-layer-style-data-schema.md。前者规定不可省略的分析维度，后者规定四层共同的数据结构；两者都不规定目标文风必须采用哪些技巧。每个维度都要留下状态，并建立参数词典：词汇保存实际词，句式保存实际结构，段落保存实际动作序列，整篇保存实际信息路线。四层参数同时写入 style-data.json，统一记录类型、频率、位置、组合和变化范围。只有目标语料支持的具体参数才能进入规则表和运行时档案。

提取结果需要长期复用或绑定到 Agent 时，默认建立以下五份档案：

文件 负责内容 普通运行是否加载
lexical-profile.md 各类型词语、同义选择、频率、覆盖、位置、搭配、功能、场景和禁用项 是；词汇是第一风格约束
sentence-profile.md 言语行为、主语与责任、焦点、条件和因果、否定、问句、命令、句长、断句和标点 由 style-profile.md 汇总；复核时完整读取
paragraph-profile.md 段首进入、中段展开、段尾退出、常见骨架、拆段、过渡和列表 由 style-profile.md 汇总；复核时完整读取
composition-profile.md 读者问题、答案位置、背景深度、证据与反例顺序、全文路线、行动和结尾 由 style-profile.md 汇总；复核时完整读取
style-profile.md 四层运行参数、主次倾向、变化触发、声音指纹、禁止项、不可迁移项和校准样例 是；作为统一运行时参数
style-data.json 四层客观参数、频率、位置、组合、变化范围及排行数据 否；供生成、复核和 HTML 使用

五份文件使用以下文件级合同：

文件 必须出现的结构
lexical-profile.md 目标语言与语料范围；逐类词典；规则 ID；实证词；状态；使用方式；频率、覆盖、位置、搭配或对照证据；置信度；未观察到和不可迁移类别
sentence-profile.md 规则 ID；规则类别；状态；适用范围；主次倾向；可观察证据；变化触发；混淆与例外；置信度；正反校准
paragraph-profile.md 与句式档案相同的规则字段；另写段首、展开、段尾、骨架、拆段、过渡和列表的适用性
composition-profile.md 与句式档案相同的规则字段；另写读者问题、答案、背景、证据、反例、行动和结尾的位置
style-profile.md 适用范围；分层验证状态；只含稳定或场景限定规则的“运行时规则”；规则 ID 回指；主次倾向；变化触发；三至五组声音指纹；禁止项；不可迁移项；正反校准与失败层级

生成 Skill 时还必须保存 style-extraction-report.json。它不是第六份风格档案，而是机器证据报告；至少包含 context、layerMaturity、bodyStyleValidation、带规则 ID 的 observations，以及 sampleFullStability、holdoutReproduction、controlDiscrimination、oneVariableTests、forwardGeneration、contentPreservation、provenanceLeakage 七项验证结果。每条 observation 必须保存规则类别、状态、适用性、主次倾向、证据、变化触发、混淆因素、验证结果和置信度，不能只写一个结论标签。每项验证必须是 passed，或在确实不适用时写成带原因的 not_applicable；未运行不能作为完成状态。

bodyStyleValidation 只审查面向人和 Agent 阅读的正文，不把标题、表格与表格数据、代码块、原始 JSON、导航和页面控件计入文风判断。审查范围至少包括目标 SKILL.md、五份正式档案、存在的答复与长文任务适配器，以及生成后的 HTML 正文。正文必须使用目标语料语言，并实际呈现词汇、句式、段落和整篇规则，不能只在表格里描述目标风格。独立任务完成复核后，保存版本、语言、所有被审查文件的正文哈希、整体源文件哈希、Markdown 与 HTML 正文哈希、四层审查结论和运行 ID；任何被审查文件改变后，旧记录必须失效。

layerMaturity 对词汇、句式、段落和整篇编排分别保存 status、unitDefinition、corpusUnits、completedChecks、missingChecks 与 evidence。status 只有 complete、partial、insufficient 三种；只有四层都为 complete，overall 才能为 complete。完成标准至少包括：词汇有分类、频率、覆盖、位置搭配、对照和复现；句式有句长分句、主语责任、焦点语序、言语行为、结构对照和人工复核；段落有可靠边界、段首、展开、段尾、骨架、拆段过渡和人工复核；整篇有足量完整文本、答案背景位置、证据反例顺序、全文路线、结尾合同、对照和人工复核。不满足的检查必须逐项列入 missingChecks，不能用前向写作测试替代来源提取证据。

生成或更新语言风格 Skill 时，还必须同步生成 style-guide.html。它是给人查看的独立阅读版和默认用户入口，不是第六份风格档案，也不是新的规则事实源。页面必须由 SKILL.md、五份正式档案和 style-extraction-report.json 自动生成；存在任务适配器或补充指标时可以一并展示。页面至少提供目录、全文搜索、分档案折叠、明暗切换和打印，不依赖外部脚本、样式、字体或图片。页面语言跟随语料语言，页面文案直接采用目标文风。

具体风格页面默认不重复讲解四层分类、提取方法、命名规则和验证合同。这些共同规则由 clear-science-writing 统一维护，并生成为 references/language-style-standard.html；读者需要时通过具体页面顶部的“通用规范”链接查看。具体页面只展示该风格实际使用什么词、怎样成句、怎样分段、怎样编排、规则何时变化以及验证结果。生成器不得把目标 SKILL.md 再展开成一个页面章节，以免把 Agent 执行说明和通用规范混进用户的风格参数阅读路径。

面向人的具体风格页面必须按固定阅读路线重组源档案：先看整体，再依次阅读词汇、句式、段落、整篇编排，随后说明四层怎样共同使用，最后进入复核区。文件边界不能决定页面顺序。四个层级使用同一信息结构：主要特征；具体类型与表达方式；常见组合或骨架；场景变化；正反样例；数据与文本依据；置信度、未验证项和不能推出的结论。不能让词汇层有完整分类，而句式、段落和整篇只保留概括。

每一层的实际结论后面必须就近附上可展开的“数据、文本依据与证据边界”。依据至少包含可观察事实、样本和全文范围、标准化频率或结构指标、覆盖率、位置和搭配、同文体或同场景对照、混淆因素、规则状态、验证结果和置信度；不适用于某一层的指标明确标为不适用。段落和整篇没有足够完整样本或人工标注时，仍展示其应分析的类型和候选骨架，但明确标注证据不足，不能把任务适配器写成来源风格。

这里的“有依据”指可追溯、可复算、可对照和可证伪，不是使用“科学证明”一类笼统措辞。一个词出现次数多，只能证明它常见；还需要覆盖、位置、搭配、对照和上下文功能，才能判断它是否具有风格区分度。句式、段落和整篇必须分别保留自己的可观察指标和人工标注依据，不能从词汇统计直接跨层推出结论。

五份 Markdown 档案和 JSON 报告改变后，必须重新生成 HTML。专用校验需要比较当前源文件与 HTML 的同步指纹；过期、手工复制、缺少正式档案或依赖外部资源的 HTML 都不能通过。Agent 普通运行不读取 HTML，避免它与正式档案形成重复上下文；用户查看、评审、打印或导出 PDF 时用系统浏览器打开它。不要把 Codex 源码查看器或文件预览当作 HTML 交付，因为这类预览可能禁用链接与脚本。除非用户主动要求原始档案，默认只向用户提供 HTML 入口。

forwardGeneration 对生成出的语言风格 Skill 始终适用，不能标为 not_applicable。通过时必须在 evidence.runs 中至少保存一条短答和一条长文记录。每条记录包含独立执行方式、运行 ID、原始中性任务摘要、结果摘要、通过状态、内容保持结果和来源泄漏结果。执行者必须是全新子 Agent 或独立任务；同一 Agent 的自我校准不能冒充独立前向测试。

需要完整机器词典和逐项指标时，另存 lexical-metrics.json。含原文、来源身份、私人路径或完整上下文的证据放在独立溯源层，普通 Skill 不加载。

每条分层规则采用统一记录方式：

规则 ID：
规则类别：语料观察 | 风格推断 | 任务适配 | 通用约束
状态：稳定 | 场景限定 | 暂定 | 否决
适用范围：
主要倾向：
次要倾向：
可观察事实与证据引用：
风格推断与输出规则：
变化触发条件：
避免方式：
混淆因素与例外：
验证结果与置信度：

四种规则不能混写：

  • 语料观察 只说明出现了什么，不用“应当”把观察改成命令；
  • 风格推断 必须回指观察证据，并说明适用场景、混淆因素和置信度；
  • 任务适配 说明怎样把风格用于答复、调查或文档，不宣称来自语料；
  • 通用约束 保存事实、安全、权限和人的权益要求，它始终优先，但不能进入声音指纹或用于证明风格名称。

style-profile.md 的运行时规则必须通过规则 ID 回指前四份档案。稳定规则可以直接进入；每条 场景限定 的来源规则和运行时规则都必须写出自己的触发条件；暂定、否决和证据不足只能留在分层档案及证据报告，不能进入运行时规则或声音指纹。三至五组声音指纹必须逐项回指已经存在的运行时规则 ID，不能只写一组无法追溯的形容词或组合。

前四份档案是各层证据和状态的事实源，style-profile.md 是运行时汇总，任务适配器只说明如何用于答复或文档。旧入口需要继续兼容时，可以保留简短适配页并链接到总参数；不要复制整套规则形成第二个事实源。

生成出的 SKILL.md 必须从一层链接直接指向五份正式档案、style-extraction-report.json 和 style-guide.html，并说明何时读取：普通运行读取 lexical-profile.md 与 style-profile.md；解释、复核或更新时读取句式、段落、整篇及机器证据；任务适配器按任务加载；用户需要浏览、搜索或打印整套档案时打开 HTML。引用不能只藏在另一份参考文件里。

超过 100 行的参考档案在顶部提供索引。所有面向人的档案使用目标语料语言与目标文风；固定文件名、规则 ID、JSON 键、命令和代码保持机器合同。

创建与验证语言风格 Skill

创建新 Skill 时遵循 skill-creator 的生命周期，不手工拼出一个无法验证的文件夹：

  1. 使用本 Skill 的初始化封装；它内部调用 skill-creator/scripts/init_skill.py，并按语料语言生成五份档案骨架：

``powershell node scripts/init-language-style-skill.mjs <skill-name> --path <输出目录> --display-name <正式名称> --language <zh|en> --description <触发说明> ``

  1. 完成语料提取，替换全部占位内容。不要让“待提取、TODO、To extract”进入最终 Skill。
  2. 根据最终 SKILL.md 重新核对 display_name、short_description 和 default_prompt；metadata 改变时使用 skill-creator/scripts/generate_openai_yaml.py 重新生成。
  3. 从当前正式档案生成给人阅读的 HTML：

``powershell node scripts/render-language-style-html.mjs <目标 Skill 目录> ``

需要立即交给用户查看时增加 --open，让系统浏览器打开页面：

``powershell node scripts/render-language-style-html.mjs <目标 Skill 目录> --open ``

  1. 先运行 skill-creator/scripts/quick_validate.py <目标 Skill 目录>，检查基础 Skill 结构。
  2. 再运行专用校验：

``powershell node scripts/validate-language-style-skill.mjs <目标 Skill 目录> [--forbid-source <作者、人物或作品名称>] ``

专用校验先检查五份档案、规则字段、证据报告、HTML 阅读版及同步指纹、直接链接、长文件索引、metadata、私人路径、来源名称，以及运行时是否混入暂定或否决规则；最终交付时再加 --require-complete。完整校验除核对四层状态外，还独立检查每层档案的必需参数、正向单位数、对照证据、可执行来源规则和通过验证的 observation；段落与整篇还必须记录人工复核。随后核对正文文风记录、目标语言、逐文件正文哈希和四层独立复核。报告自称 complete、正文只在表格里描述文风，或修改正文后仍沿用旧复核记录时都必须失败。结构通过但成熟度为 partial 或 insufficient 的结果只能作为未完成提取，不得标为正式完成版。

  1. 使用全新子 Agent 或独立任务执行至少一个短答和一个较完整文档的前向测试。只传目标 Skill 路径和原始用户任务，不传预期答案、缺陷诊断或拟议修复；把运行 ID、执行方式、任务摘要、结果摘要、内容保持和来源隔离结果写入 validation.forwardGeneration.evidence.runs。记录结果后再修改 Skill，重新生成 HTML，并重新执行两种校验和前向测试。

验证提取结果

至少完成以下验证：

  1. 样本与全文：固定样本发现的方向在全文中是否仍成立；若改变，说明漂移来自哪里。
  2. 保留样本：未参与规则发现的文本是否仍能被档案解释。
  3. 对照区分：同语言、同文体对照是否也同样具备该特征；若是，它可能只是共有写法。
  4. 单变量对照：只改变一个词、主语、句尾、断句或顺序，检验推定效果是否真的由该变量造成。
  5. 完整前向生成：用相同事实生成短答、段落和较完整文档，检查四层选择是否共同出现，而不是只插入代表词。
  6. 内容保持：事实、责任、数字、代码、安全和审批边界是否完全保留。
  7. 来源隔离：普通输出是否没有作者、人物、作品、世界观、原句和私人路径。

验证失败的规则降为“场景限定”或“暂定”，无法排除题材和单场景影响时标为“否决”。

命名语言风格

名称在 LexicalProfile、NonLexicalStyleProfile 和最终 StyleProfile 通过样本外复核后确定。它是对可迁移语言机制的短称，不是来源标签。

  • 中文正式名称使用“二至四字核心特征 + 语言风格”。核心特征优先概括推理、节奏、叙事推进、语气控制或词汇选择，例如“理性推演语言风格”“危机推进语言风格”。
  • 英文正式名称使用简短特征短语加 Language Style，通常控制在一至四个实义词。
  • 名称不得包含作者、人物、作品、文件名、站点名、粉丝称呼或其他来源身份。来源只写入溯源记录和证据说明。
  • 不用“高级、独特、强烈、冷酷”等缺少判断对象的形容词命名。名称必须能对应档案中已统计、可复核的选择。
  • 对白、叙事、说明文或其他文体若形成不同词汇与声音指纹，应分别命名。只有样本外测试证明它们共享主要选择时，才建立总称。
  • 名称不是永久标识。新语料改变结论时可以改名；全局或跨任务绑定只引用稳定的“当前语言风格”入口，由它映射到现行 Skill 或档案。更换风格时只修改映射，不修改每一处全局提示词。

若产物是 Skill，还要同步迁移它的对外身份：

  • 正文标题和界面 display_name 使用目标语言正式名称；Skill 目录 slug 与 frontmatter name 使用与该正式名称对应、来源中立的 ASCII kebab-case。例如“理性推演语言风格”可映射为 rational-inference-language-style；
  • frontmatter description 与触发说明只写可观察的词汇、句法、节奏、篇章和适用任务，例如“在需要条件分析、概率判断和明确行动结论时使用”；
  • 不写“模仿某人”“某作品风格”或把来源名称当关键词；
  • 作者、人物、作品和原始文件名只写入独立的 source-provenance 一类溯源文档。普通调用不加载该文档，只有复核来源、更新档案或查询证据时才读取。
