# 提取词汇档案

词汇是第一风格约束。人称、情态、程度、评价、语气词和句首句末习惯一旦改变，即使事实与句式不变，读者感受到的身份、距离和态度也会改变。

## 两遍提取

第一遍按分类词表搜索，回答每个类别中实际出现了什么。第二遍做开放发现，寻找分类表没有预设但在语料中反复出现的词、短语、句首、句末和固定组合。

如果只做第一遍，结果会被参考词表限制，语料中真正稳定的说法可能被漏掉。如果只做第二遍，高频题材词又会淹没人称、情态和语气词。因此两遍都必须完成。

## 统计方法

语料较大时先运行：

```powershell
node scripts/analyze-lexicon.mjs <文本文件或目录> sample-report.json --sample-size 120 --sample-seed 42 --sample-strategy random --min-paragraph-chars 20
```

脚本接受 `.txt`、`.md` 和 `.jsonl`，根据全部有效正文判断中文或英文，输出分类计数、每万字符或词的标准化频率、文档与段落覆盖、句首句末和段首段尾位置、左右搭配候选、开放词汇候选、词类组合和基础非词汇指标。句长变化只在同一段内部计算，词类共现也不会被直接解释成言语行为。Markdown 的围栏代码、行内代码、链接目标和裸 URL 不进入词频、句长、逻辑词或开放词汇统计；链接文字和去掉列表、引用、标题标记后的正文仍保留。普通正文软换行、连续引用行和列表续行会合并为一个分析段落，新的列表项与嵌套列表项仍各自成段。`corpus.sourceRecords` 记录解析器看见的正文与排除记录总数，`corpus.sourceParagraphs` 只记录可分析的真实段落，不能混用。`.txt` 与 `.md` 以文件为文档，`.jsonl` 以每条含文本记录为文档；JSONL 依次读取 `quote`、`text`、`content`、`paragraphText` 中第一个非空字符串，并在 `corpus.jsonlDiagnostics` 报告跳过或按原文使用的异常行。文件覆盖、段落覆盖和说话场景覆盖不能混写。混合语料仍须先按语言分组，不能把自动判断当成分组。默认不保存原文句子；只有显式使用 `--sample-output` 时才写出本地样本。报告默认把文件来源匿名化，不写本机绝对路径。任何统计都不能替代上下文判断。

`LexiconScanReport` 当前为 Schema v3。v3 新增 `sourceRecords`、段落层指标、词类组合与 `pathMode`，并把默认来源字段改成匿名标签；读取旧 v2 报告或维护下游脚本时，必须按版本分支处理，不能假定 `corpus.input`、`corpus.files` 和 `paragraphReferences.file` 一定是可访问路径。

推荐流程：

1. 用 `--sample-size 100` 到 `300` 做初次随机样本，固定 `--sample-seed`。
2. 如果材料跨多个文件或前后差异明显，改用 `--sample-strategy stratified`。样本数不少于有效文档数时，脚本先保证每个文档至少一段，再把剩余名额分配到全文位置。
3. 需要阅读原段落时使用 `--sample-output <private-sample.jsonl>`；把它保存在输入语料目录之外，不要提交到仓库或公开 Skill。脚本会跳过自己生成且带标记的样本文件，但历史导出文件仍需人工隔离。
4. 默认保留 `--path-mode anonymous`。私人复核若需要识别来源文件，使用 `--path-mode relative`；`--path-mode absolute` 只用于本机排障，生成的报告不能公开或写入可分发 Skill。
5. 从样本中发现分类表未覆盖的词与短语，保存为 JSON，例如 `{ "自定义判断词": ["倾向于", "更可能"] }`。
6. 用 `--terms-file <词表.json>` 重新执行；`--terms-mode merge` 合并内置分类，`only` 只统计自定义词表。
7. 样本结论稳定后，再用 `--sample-size 0` 扫描全部非空段落，验证频率和分布是否仍然成立；如果仍需排除短行，再显式传入 `--min-paragraph-chars`。

`--sample-size` 只限制进入统计和人工样本的段落数。脚本仍须先读取、解码并切分全部输入，以便判断语言和建立抽样总体，因此它不是内存限制。超大单文件或大量 JSONL 记录应先在私人目录按语言、章节、场景或来源拆分，再分批运行并保存各批分母；不能把几批覆盖率直接相加当成全局覆盖率。

还可以使用 `--min-paragraph-chars` 排除过短正文，使用 `--open-top` 控制开放词汇候选数量，使用 `--min-count` 隐藏低于指定次数的参考词。被隐藏但实际出现的词进入 `belowMinimumForms`，不会混入 `absentReferenceForms`。

类别可以重叠，短语也可能包含单词，例如“这是什么”会同时命中短语和“什么”。因此分类总数不能相加当作唯一词数；它们只用于比较同一类别中的偏好。词类组合要求同一句或同一段至少出现两个不同词形；“可能”同时属于“确定程度”和“缓和”时，单独一个“可能”不会生成这两个类别的组合。即使出现了两个不同词形，共现仍不是言语行为结论，必须回看上下文。中文单字只把分词器识别出的独立单字记入确认次数；“不走、我去、别人、去年、没收”中的单字子串都进入 `ambiguousReferenceForms`，不会自动算成对应功能词，也不能写成“未出现”。Agent 必须回看上下文，再决定是否把候选加入自定义短语或人工结论。

不要只输出词频表。每个候选词或短语至少记录：

```text
词或短语：
功能类别：
总次数与标准化频率：
覆盖了多少篇、章节或说话场景：
覆盖了多少段和多少句：
常见搭配：
常见位置：句首／句中／转折／结尾／单独成句
实际作用：提问／保留／强调／否定／评价／行动等
可能混淆的其他作用：
对照组差异：
是否可迁移：
```

中文同时统计单词、二至六字短语和句末组合。例如“什么”“这是啥”“这是什么”“什么意思”不能只合并成一个“疑问词”数字。英文需要统计词形变化、缩写、情态动词、短语动词和句末附加问句。

频率必须标准化，例如每万字、每千词或每百段出现次数。再检查分布：一个词出现一百次但集中在单章，不如一个词在二十篇材料中都稳定出现更能说明文风。

一本书或一份长记录若只放在单个 `.txt` 文件中，文档覆盖率几乎只能是零或一。此时优先查看脚本新增的段落覆盖率，并在私人预处理层把章节、说话场景或文章拆成独立 JSONL 记录，再把记录覆盖解释为对应逻辑单元覆盖。报告必须写清覆盖分母究竟是文件、记录、段落、章节还是场景，不能互换名称。

## 逐类回答“主要用什么”

每个词类都要生成一条实际分析，不允许只复制分类说明：

```text
类别：疑问词与疑问短语
语料实际出现：什么 42、怎么 18、为什么 9、啥 0、何种 0
主要偏好：以“什么、怎么”为主，不使用“啥”，书面疑问“何种”也未出现
位置：多数位于直接问句中；少量“什么”出现在反问句
稳定组合：这是什么、什么意思、怎么可能
作用：索取信息为主，反问为辅
覆盖：分布于 11/14 个样本，不是单篇集中
置信度：较高
```

数字只是格式示例，不能写入其他语料的结果。没有对应词时写“未观察到”，不要从参考表补一个看起来合理的答案。

同义词必须放在同一组比较。例如：

- 什么／啥／何种；
- 怎么／咋／如何；
- 为什么／为啥／缘何；
- 但是／不过／然而；
- 应该／必须／建议／可以；
- 很／挺／非常／极其；
- 其实／问题是／严格来说；
- 吧／呢／啊／啦／哦。

文风往往来自“选择了哪个，没有选择哪个”。因此零次出现也可能有意义，但只有语料规模足以支持时才能解释。

| 语域词 | 啥／什么／何种，咋办／怎么办／应如何处理 | 口语、中性、正式或古典程度 |
| 网络、方言和圈层词 | 离谱、稳了、整、搞、这玩意 | 年龄感、地域感和群体身份 |
| 外来语与缩略语 | OK、NG、UI、KPI、deadline | 行业、代际、跨文化语感和读者门槛 |
| 专业术语 | 架构、耦合、留存率、帧同步 | 专业身份和读者门槛 |
| 带评价的名词与动词 | 砍掉、阉割、塞、拍脑袋、鸡肋 | 不通过形容词也能表达褒贬和攻击性 |

类别不是固定词典。“可能”主要表示确定程度，不应因为常出现在条件句里就统一算作条件词；“别”是禁止词；“直接”通常描述行动方式；“可以”要根据上下文区分许可、能力和可能性；“应该”要区分义务、建议和推断；“其实”可能是修正词，也可能只是无意义起手词。

礼貌程度、行动压力和判断确定性必须分开标注。“请务必停止”很礼貌，但仍是强制要求；“我不确定原因，但必须先停机”判断保留，却不降低行动压力。不要把它们压成一个“语气强弱”数字。

## 句首、句末与组合

单词频率不足以解释个人风格，还要统计位置：

- 句首：其实、问题是、简单说、说白了、严格来说、老实说、首先、那么、你看；
- 句末：吧、呢、啊、啦、呗、哦、哈、对吧、是不是；
- 否定组合：并不是……而是、不能说……只能说、不是因为……而是因为；
- 条件组合：如果……那么、只要……就、除非……否则；
- 不确定组合：可能是……也可能是、目前更倾向于、还不能排除；
- 决策组合：应该先……再、必须在……之前、可以……但是；
- 重复组合：真的很、不是……不是、不能……不能。

句首词决定说话者怎样进入问题，句末词决定他怎样退出一句话。两者通常比正文中的主题名词更容易形成稳定辨识度。

## 多类词怎样共同出现

单个词只能说明一个局部选择，稳定声音通常来自多类词在同一句或同一段中的组合。至少检查：

- 人称或称呼 + 确定程度 + 行动词；
- 判断依据 + 因果或修正词 + 范围限定；
- 程度词 + 评价词 + 句末语气词；
- 请求或礼貌词 + 命令或禁止词；
- 句首进入方式 + 句末退出方式；
- 口语、书面、专业、方言和缩略语是否处在同一语域。

报告组合时记录共同出现的句数、段数、覆盖率和相对独立出现的比例。组合类别可能重叠，不能把共现直接解释为因果；它只说明哪些选择经常一起出现。再回看原句，判断组合实际形成的是协商、说明、试探、命令、吐槽还是别的言语行为。

需要检验某个词是否真的造成某种阅读效果时，制作单变量对照：保持事实、句法和上下文不变，只替换该词或句尾，再检查效果是否随之变化。如果必须同时改动人称、句长和段落顺序，不能把变化只归因于这个词。

## 开放发现

分类表之外继续检查：

- 高频实词：最常使用的动作词、评价词、抽象名词和具体名词；
- 二至六词或二至十二字的高频组合；
- 重复出现的句首三至八字和句末二至六字；
- 某个词前后最常共现的词；
- 只在目标作者、说话者、团队或文体中明显偏高的词；
- 高频但只属于主题、情节、产品或行业的词。

开放发现得到的词仍要回到上下文判断功能。不能因为“系统”出现最多，就把文风命名为“系统式”；也不能因为某个说话者总在特定场景里说“计划”，就直接认定所有输出都应反复使用“计划”。

## 区分来源词与内容词

将候选词分为四层：

1. **稳定来源词**：跨主题、跨位置、跨样本承担相同作用。
2. **低频来源词**：有特征，但证据不足，只在匹配情境中使用。
3. **内容与题材词**：人物名、产品名、世界观、事件对象和行业对象，不作为通用风格迁移。
4. **任务工作词**：目标任务必须保留的术语、风险词和责任词，可以使用，但不冒充来源风格。

词频高不等于可迁移。只有位置、搭配、功能和跨样本分布同时稳定，才能写入来源词汇档案。

```text
禁止项：
```

逐类统计报告保留完整证据，`LexicalProfile` 只压缩稳定结论。不要把几百个词全部塞进最终提示词；按类别保存统计，在写作时选择与当前句子功能匹配的来源词。

`LexicalProfile` 先约束词汇，`StyleProfile` 再约束句式、段落和语气。生成正文后检查来源词是否真的进入用户可见输出；如果存在对应功能却完全没有来源词，说明绑定没有执行。如果词删掉后意义不变，说明它只是模仿痕迹。

## 机器可读报告

语料较大或需要复核时，同时保存机器可读结果。脚本直接生成的是 `LexiconScanReport`，用于保存机械扫描证据；最终 `LexicalProfile` 还需要 Agent 结合上下文补齐功能、题材边界、可迁移结论和置信度，二者不是同一份 Schema。下列 JSON 只示意两层都必须保留的证据字段，不是脚本完整输出的逐字段定义：

```json
{
  "language": "zh",
  "corpus": { "documents": 0, "characters": 0, "sentences": 0 },
  "categories": [
    {
      "category": "疑问词与疑问短语",
      "totalHits": 0,
      "normalizedRate": 0,
      "dominantForms": [
        {
          "term": "什么",
          "count": 0,
          "documentCoverage": 0,
          "paragraphCoverage": 0,
          "positions": {},
          "collocations": [],
          "functions": []
        }
      ],
      "alternativesCompared": [],
      "finding": "",
      "confidence": ""
    }
  ],
  "styleMetrics": {
    "categoryCombinations": {
      "sentences": {},
      "paragraphs": {}
    }
  },
  "openVocabulary": [],
  "topicTerms": [],
  "transferableRules": [],
  "uncertainFindings": []
}
```

字段可以随目标语言调整，但必须保留“实际词、次数、覆盖、位置、搭配、结论和置信度”。这样下一次更新语料时，才能判断词汇偏好是否真的发生变化。
