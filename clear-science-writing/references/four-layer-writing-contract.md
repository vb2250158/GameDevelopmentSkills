# 四层文风维度合同

本合同定义客观特征的检查空间。完整四层类型轴和模板库见 [four-layer-type-catalog.json](four-layer-type-catalog.json)，原始人类阅读版见 [文风参数化方法论_四层类型字典版.html](文风参数化方法论_四层类型字典版.html)，原始数据版见 [文风参数库_四层类型字典.json](文风参数库_四层类型字典.json)。参考材料中的例词、例句、句式、段落序列和全文路线只能作为候选字典，不能直接成为目标风格结论。目标风格的全部实际取值、频率和使用条件必须从目标语料中提取。

## 基本规则

1. 按词汇、句式、段落、整篇编排四层分析。阅读效果是四层共同产生的结果，不是第五层。
2. 每个维度都必须留下状态：稳定、场景限定、暂定、否决、未观察到、不适用或证据不足。
3. 每个成立的取值都必须记录分析单位、数量或比例、分布、位置、组合、同类对照、场景变化、混淆因素、验证结果和置信度。某项指标不适用时明确说明原因。
4. 维度用于提出问题，不能预先给出答案。分析者不得因为参考材料列出过某种写法，就把它写成目标风格。
5. 每层使用本层证据。词汇证据不能替代句式证据，句式证据不能替代段落证据，局部文本不能替代整篇证据。
6. 四层统一记录类型、频率、位置、组合和变化范围。完整字段及 JSON 合同见 [four-layer-style-data-schema.md](four-layer-style-data-schema.md)。
7. “冷静、专业、温和、强硬、成熟”等只能作为数据解释后的阅读效果，不能成为一级分类，也不能替代客观参数。
8. 候选库和目标参数必须分离保存：候选库回答“检查过什么”，目标参数回答“语料实际用了什么”。候选项即使零次或暂时无法可靠识别，也必须在候选库、审计字段或独立检查报告中留下状态；零命中项不得写入具体语言风格 Skill 的正式参数、目标字典或正文。
9. 每个参数统一记录五项共同属性：类型、频率、位置、组合、变化范围。词汇、句式、段落和整篇不能使用不同的完成标准。
10. 完成度由数据反推。存在 `not_measured`、`insufficient_evidence` 或未经语义复核的自动候选时，相应层不得标为 `complete`。
11. 目标风格字典允许随新语料和真实使用反馈迭代，但生成结果不能成为自证数据。目标原文、用户修订、用户明确接受、用户否决和未经确认的模型输出必须分开记录。

## 维度与参数

维度说明“分析哪一方面”，参数说明“目标语料在这一方面实际怎样写”。两者不能合并。

- 词汇维度的参数是实际词、短语、同义选择、固定搭配和位置；
- 句式维度的参数是实际句类、问法、否定或纠正结构、逻辑连接形式、主语形式、语序、句长组合和标点形式；
- 段落维度的参数是实际段首动作、中段展开动作、段尾动作、段内序列、长度形态、拆分与承接方式；
- 整篇维度的参数是实际信息位置、排序依据、推进路线、展开深度和结尾功能。

例如，“纠正方式”是句式维度；“不是 A，而是 B”只有在目标语料中实际出现并完成统计后，才是该风格的句式参数。“疑问方式”是维度；“……吗”“什么／为什么／怎么”可以成为参数，而反问若未完成独立标注，就只能保留为未验证参数。参数记录的是语料事实，不是推荐技巧。

为了便于理解，可以把风格类比为一个受上下文约束的参数系统：

```text
当前任务、语义、读者、关系、风险和前文
→ 激活各层相关维度
→ 判断维度内哪些参数更适合当前语境
→ 联合选择词、句式、段落动作和整篇路线
→ 生成当前表达
```

这只是帮助理解的类比，不是实现规范。Skill 不建立神经网络、注意力机制或虚构概率。数据充分时记录频率、覆盖、对照差异和使用条件；数据不足时如实记录未确定。任何参数都不能因为具有辨识度，就在每句话中重复。

## 第一层：词汇维度

逐类分析实际用词、同义选择、位置、搭配、功能、覆盖和对照差异。至少检查：

- 人称系统；
- 称呼系统；
- 指示与回指系统；
- 群体边界与身份指向；
- 判断确定程度；
- 判断依据与立场来源；
- 决策与行动强度；
- 命令、禁止、请求与许可；
- 时间压力与阶段；
- 程度；
- 范围；
- 频率；
- 评价方向与评价对象；
- 情绪方向、强度和显隐；
- 强调、缓和与绝对化；
- 否定；
- 疑问；
- 句末语气；
- 回应与反馈；
- 感叹、拟声与现场反应；
- 逻辑连接；
- 顺序组织；
- 总结、修正与补充；
- 句首习惯与填充；
- 口语、书面和正式程度；
- 网络、地域、时代、文言和圈层标记；
- 专业词、外来语与缩略语；
- 固定领域词和比喻来源；
- 稳定搭配、固定位置、禁用词和稳定缺席项。

词汇层必须产生逐类词典。当前通用目录包含8个大类、193种词汇类型和对应候选词条；它们用于下一轮冻结扫描和开放发现，不能覆盖已经存在的目标统计。通用候选词形必须标明扫描范围；目标词典只收录语料实际命中的词或经过开放词汇复核确认的同义表达，并默认按覆盖率或命中率从高到低排列。候选词零次不能推出整个语义类别不存在，也不能成为目标风格参数。

### 人类阅读版的数据驱动词汇字典

词汇层的 HTML 只从统一词汇数据生成，不维护第二份手写词表。生成器同时输出 `vocabulary-dictionary.json`，供复核、导入和其他工具读取；该文件必须与 HTML 内嵌数据一致。字典把两类信息分开保存：

- 通用分类信息：大类、类型名称、定义、作用、使用场景、注意项、信号和核心／扩展标记；
- 目标语料信息：实际词形、次数、标准化频率、覆盖、位置、组合、变化、对照和验证状态。

一个词可以进入多个类型。词条索引应按词形合并类型关系，但不能把不同类型中的次数或功能强行归并成单一语义。页面统计数字由当前 JSON 自动计算，并支持类型浏览、词条反查、多重归类筛选、数据编辑和 JSON 导入导出。修改通用分类不会自动产生目标语料计数；缺少统计的新增类型仍应明确显示为未测量。

### 人类阅读版的数据驱动句式字典

句式层先回答“一句话客观上属于哪些类型”，再回答“它使用了哪个具体模板”。通用字典因此分成分类轴、句式类型和具体模板。目标语料统计另行保存并映射到模板；类型统计只能由已映射模板汇总，不能把通用类型数量当成目标频率。

目标语料中的新句式若尚未与通用模板建立唯一对应，必须保留为目标文风扩展。随着新语料进入，目标字典可以不断增加；升级通用字典则需要跨语料复现、人工确认边界和可复核的识别条件。

### 人类阅读版的数据驱动段落与整篇字典

段落层与整篇层采用和句式层相同的双层结构：先按多个客观分类轴判断类型，再查看完整的句子功能序列或全文模块序列。段落通用目录包含8个分类轴、112种类型和65个模板；整篇通用目录包含9个分类轴、118种类型和60个模板。

通用类型和模板只回答“检查什么”。目标语料的次数、位置、组合、变化和验证状态单独映射。自动功能标签与通用模板无法唯一对应时，保留为目标扩展；人工标注完成前不能强行归类，也不能把未映射解释为未出现。

### 日常样本与持续更新

日常写作产生的反馈可以补充目标风格，但进入正式统计前必须经过来源判断：

- `source_corpus`：目标原文，可以参与来源规律统计；
- `user_revision`：用户亲自修改后的文本，可以参与任务适配统计；
- `user_accepted`：用户明确接受的生成文本，可以作为适配样本，不能反推原作品规律；
- `user_rejected`：用户明确否决的文本，只作为反向样本；
- `model_candidate`：未经确认的模型输出，只能提出候选，不计入正式频率。

维护任务将最小必要记录写入 `style-learning-log.jsonl`。记录至少包含样本 ID、时间、语言、来源类型、决定、文本哈希或受控本地引用、涉及层级、候选参数和复核状态。更新时先去重，再分别统计来源语料和适配语料；两者不得合并成一个频率。用户没有要求维护 Skill 时，普通写作任务不得静默写入该日志。

## 第二层：句式维度

分析词汇怎样组成一句话。至少检查：

- 句类分布；
- 言语行为分布；
- 主语类型；
- 主语出现、省略与恢复；
- 责任主体的明确程度；
- 主动、被动、状态和无人称表达的分布；
- 视角与判断归属；
- 语序；
- 话题和焦点位置；
- 句首与句尾的信息落点；
- 插入信息的位置与形式；
- 肯定方式；
- 否定方式；
- 限定方式；
- 纠正方式；
- 逻辑关系类型及其显化程度；
- 关系组合数量和层级；
- 简单句、并列句、主从句和省略句的分布；
- 分句数、嵌套深度、指代负担和关系链长度；
- 句长分布与离散程度；
- 相邻句长变化和长短组合；
- 完整句、碎片句和故意断裂的分布；
- 重复方式；
- 平行与递进方式；
- 标点分布；
- 断句位置与语义边界；
- 不同场景下句式参数怎样变化。

句式档案必须建立完整候选模板库，并分别回答这些维度的实际取值、功能和证据。每种句式至少记录名称、模板、语法或逻辑关系、识别标记、每百句次数、覆盖率、位置、组合、变化范围、对照差异和验证状态。不能把词频当作句法证据，也不能把候选模板直接当作目标风格。

句式参数必须尽量写成可识别形式，例如抽象槽位、标记词、语序关系或标点结构。只写“偏理性、逻辑较强、常用转折”不算参数。

## 第三层：段落维度

分析若干句子怎样完成一个局部任务。至少检查：

- 段落的中心任务；
- 段首功能；
- 中段展开功能；
- 段尾功能；
- 段内动作序列；
- 主干信息与辅助信息的关系；
- 事实、判断、原因、证据、例子、条件、反例、步骤和行动在段内的位置；
- 段落长度分布；
- 单句段与多句段的比例和功能；
- 拆段触发条件；
- 合段条件；
- 相邻段落的承接方式；
- 过渡的显式程度；
- 自然段、列表、表格、引用和提示块各自承担的功能；
- 不同场景下段落参数怎样变化。

段落层必须建立句子功能序列候选库，例如“问题 → 原因 → 解决办法”这一类可检查结构；它只规定检查范围，不规定目标语料必然采用。目标段落骨架必须从完整段落的人工标注中归纳，不得用单句对白或自动功能标签替代人工边界判断。

## 第四层：整篇编排维度

分析各段怎样安排读者的理解顺序。至少检查：

- 文本目的；
- 主要读者；
- 读者已有信息；
- 读者首要问题；
- 开头最先释放的信息类型；
- 核心答案或判断的位置；
- 背景的位置和深度；
- 原因与机制的位置；
- 证据的位置和次序；
- 例子的位置和次序；
- 反例、异议和限制的位置；
- 方案、比较和选择的位置；
- 行动、责任主体和时间的位置；
- 成功标志、失败处理和恢复信息的位置；
- 信息排序依据；
- 全文推进路线；
- 展开深度；
- 结尾功能；
- 媒介、用途、读者和风险变化怎样改变编排；
- 哪些编排属于来源风格，哪些只是任务格式或文体惯例。

整篇层必须建立内容模块及其顺序候选库，记录模块类型、出现频率、常见位置、前后组合和场景变化。目标整篇路线必须从足量完整文本中归纳；候选库不预设答案先行、时间顺序、问题解决、悬念推进或任何其他路线是目标风格。

## 维度检查矩阵

四份分层档案都必须包含维度检查矩阵。每行至少记录：

```text
维度：
状态：
目标语料的实际取值：
分析单位与样本范围：
数量、比例或结构指标：
位置与组合：
实际功能：
同类对照：
场景变化：
混淆因素：
验证结果：
置信度：
能推出什么：
不能推出什么：
```

矩阵负责证明所有维度都已检查。稳定和场景限定的取值才可以进入规则表；暂定、否决、未观察到、不适用和证据不足项保留在矩阵中，但不得进入运行时规则。

## 参数词典

四份分层档案还必须包含参数词典。每个参数单独占一行，至少记录：

```text
参数 ID：
所属维度：
具体形式：
语料语言中的实际例项或抽象槽位：
使用倾向：
常见条件：
减少使用或不适用的条件：
次数、标准化频率与覆盖：
常见位置与组合：
实际功能：
状态：
适用场景与变化条件：
同类对照：
混淆因素：
验证结果与置信度：
不能推出什么：
```

词汇参数词典列实际词语；句式参数词典列实际结构；段落参数词典列实际局部动作序列；整篇参数词典列实际信息路线。只有维度名称，没有具体参数，不能称为完整文风档案。

四层参数还必须写入统一的 `references/style-data.json`。Markdown 表格不能成为唯一数据源。常用句式必须按实际次数排序，并给出每百句次数、覆盖率、位置、组合、同类对照和变化范围；只列“如果 A，那么 B”“不是 A，而是 B”等模板而没有统计，不算完成。

生成时不得逐表机械遍历参数。先按当前语义和场景选择相关维度，再根据语料证据和使用条件选择参数；多个层级的参数冲突时，事实、安全、责任和读者可理解性优先，其次才是风格复现。

## 四层校验

使用同一组中性事实分别检查词汇、句式、段落和整篇参数。校验只改变被测试的层，其他事实和表达条件保持不变。正向样例必须由目标参数生成；反向样例要指出失真发生在哪一层。任何校准都不得引入参考材料中的固定技巧，也不得改变事实、责任、安全或审批边界。
