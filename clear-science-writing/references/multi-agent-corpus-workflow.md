# 多 Agent 全语料文风提取与评分工作流

本流程只适用于“根据目标语料创建文风 Skill”。直接根据用户反馈创建的风格没有语料，不得伪造采样、全文统计或评分校准。

## 硬门槛

在任何候选词、句式、段落骨架或内容路线写入正式 `style-data.json` 之前，必须完成：

1. 先建立全文索引：每个输入文件按前、中、后位置和自然单元切片；每个文件都必须进入抽样总体。
2. 至少启动四个彼此独立的审阅任务：词汇、句式、段落、整篇编排。语料很小时也不能把四层合并成一次泛读。
3. 每位审阅者都从自己被分配的片段抽样，记录看过的文件、位置分层、样本数、规则候选、功能、反例、题材混淆和可迁移边界。
4. 汇总者只合并有来源记录的候选；不得把通用目录或脚本的候选项直接升级为目标文风。
5. 先完成跨审阅的语义复核，再把确认词表／句式表／结构表交给全文脚本回扫次数、覆盖、位置和组合。
6. 全文回扫只验证已确认的候选，不能凭高频结果自行加入新规则。新发现项回到人工候选队列，至少由一位原层审阅者复看后才能回扫。
7. **分类、命名、功能、场景与边界也必须先来自人工分析。** 脚本、渲染器和评分器只能读取这些已确认字段，计算次数/覆盖/位置/分数并展示它们；不得根据正则、命中频率或通用目录自动新建、合并、重命名“句式类型”“段落类型”或内容路线。

缺少任一步时，对应层只能标为 `partial` 或 `insufficient`；不得叫“完成的文风”。

## 采样覆盖

### 切片与分配

- 对每份文本建立相对位置分层：开篇、中前、中段、中后、结尾；短文本按自然段或章节保持可解释的等价切片。
- 每位审阅者都要看见每份源文本至少一个片段；长文本额外按层数和规模分配样本，优先覆盖说话场景、叙述段、冲突段与收束段。
- 默认每层至少 120 个有效段落或同等数量的完整句／章节单元；跨多文件时采用分层抽样，不能只随机抽到大文件。
- 大语料可提高到每层 200–400 个单位。目标不是让 Agent 逐字遍历，而是让全部文件、全部相对位置和主要场景进入“人工见过”的抽样记录，再以全文脚本补足分布证据。

### 四个独立审阅任务

| 审阅任务 | 最小记录 | 禁止的捷径 |
|---|---|---|
| 词汇 | 二至六字词、固定搭配或槽位表达；功能、同义替代、位置、搭配、题材风险 | 不能把单字、助词、人名、器物名或主题名词直接写进 Skill。 |
| 句式 | 具体模板、标记、言语行为、焦点、句长与停顿、正反例 | 不能把单一标点或连接词当句式。 |
| 段落 | 段首、展开、段尾、动作序列、拆段和过渡 | 不能仅按段长或逐句词频推断骨架。 |
| 整篇 | 文本用途、开头信息、背景位置、事件／证据推进、结尾合同 | 不能从一个章节或一段对白推断整篇路线。 |

每个候选最少包括：`layer`、`form`、`function`、`sampleEvidence`、`sourceDistribution`、`confounds`、`transferScope`、`reviewerDecision`。原文样本仅保存在私有审计层；正式 Skill 只保存匿名统计和可复核结论。

正式 `style-data.json` 的每条参数还必须保留 `manualAnalysis`：`category`、`function`、`sceneCondition`、`evidenceSource`、`reviewStatus`。若这些字段没有人工来源，页面必须显示“未分类候选”，评分器不得将其算为一个新类别或总分特征。

## 从微观到宏观的执行顺序

1. **建立总体与切片。** 记录全部源文件、有效单位数、分层方案与保留样本。
2. **多 Agent 微观审阅。** 先词汇与具体句式，确认什么是表达方式、什么只是题材。
3. **中观审阅。** 独立标注段首—展开—段尾、对话与动作交替、转场与拆段。
4. **宏观审阅。** 以完整章节或文本单元标注开头、背景、推进、信息释放与结尾。
5. **合议与反例。** 找出重复出现的候选，也记录看似高频但只属于人物、设定、章节或事件的反例。
6. **全局回扫。** 用合议后的封闭表测量全文频率、标准化频率、段落／章节覆盖、位置、搭配和对照差异。
7. **保留样本与前向测试。** 用未参与发现的样本检验解释力，再由独立任务生成短文和长文检验四层共同出现。
8. **生成 Skill 与评分配置。** 只有稳定且校准的参数进入运行时规则、HTML 与评分器。

## 不压扁文风：变体谱系

小说常同时使用日常互动、连续对白、内心判断、场景铺陈、设定解释、误解玩笑、冲突、高压和收束等多种手法。提取时不得只挑一条“核心路线”当成整个文风，也不得因为某种写法低频就自动删除。

- 每层都按 **主倾向／次倾向／场景限定／低频有效变体／反例或题材混淆** 五栏保存。
- 词汇至少分关系、判断、行动、范围、情绪、叙述声音、对白回应、句首进入、句末收束；同一词在不同功能中分别记录。
- 句式至少分对白问答、内心判断、叙述动作链、解释或设定、玩笑或误解、冲突或高压、转场和收束；模板可重叠，但不能因为同一个标记字重合而合并。
- 段落和整篇同时记录场景型、对白型、解释型、关系型、冲突型、转场型和收束型路线。低频高压路线以触发条件保存，不能让普通日常文本因没有它而失分。
- 另建 **手法—情节模式矩阵**：每个已见模式记录“触发条件 → 可选表达簇 → 段落/篇章结构 → 反例”。例如“悲剧/高压后的轻喜剧回落”“误会的喜剧升级”“总结或解释段的降速写法”必须分别记录；不能把它们平均成一条所谓通用文风。
- HTML 默认按覆盖率排序，但必须能查看全部通过人工复核的参数；“核心”只影响默认权重，不是把其他已见手法藏掉。
- 评分器先识别输入文本的场景，再只启用该场景适用的特征集合；未触发的场景限定规则显示“不适用”，不扣分。

## 评分器的校准合同

每个由语料生成的风格 Skill 都必须带：

- `scripts/score-style.mjs`：对传入文本输出 JSON 或简表；
- `references/style-score-config.json`：由正式 `style-data.json` 派生，保存每层可执行特征、基线与校准状态；
- 至少一个正向和一个反向测试文本，以及预期“哪一层更高／更低”的验收记录。

评分器输出四层分数和总分，但有三条不可妥协的边界：

1. 未经人工校准的层显示 `未评分`，不以零分冒充失败，也不计入总分。
2. 分数只描述“已校准特征的匹配度”，不证明作者身份、作品来源、版权归属或文本质量。
3. 词汇命中不可以单独代表句式、段落或篇章；四层必须分别有特征和基线。

校准一层至少要有：多 Agent 样本中的人工语义结论、全文回扫的统计基线、明确的特征识别算法，以及正反文本测试。段落和整篇若只有人工语义标签、没有可靠算法，评分器应输出该层的人工复核提示，而不是杜撰自动分数。

对场景分支，评分报告还必须给出：检测到的场景标签、启用的手法簇、未启用而不适用的簇、以及“仅有表层词/模板但场景不成立”的误命中提示。总分只能汇总适用簇；单独的“悲剧写喜剧”“总结式收束”等复杂手法在没有足够结构化标注前只能输出置信度受限的诊断。

## 生成后验收

在常规文件／结构校验、七项提取验证之外，必须执行：

```powershell
node scripts/build-style-score-config.mjs <目标 Skill 目录>
node scripts/score-language-style.mjs <目标 Skill 目录> <正向测试文本> --json
node scripts/score-language-style.mjs <目标 Skill 目录> <反向测试文本> --json
```

验收结果应确认：输入能被读取；输出含分层证据；只有已校准层进入总分；正向样本的已校准分数高于反向样本，或明确记录无法区分的层与原因。
