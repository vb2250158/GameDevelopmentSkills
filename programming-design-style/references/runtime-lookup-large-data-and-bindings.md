# 运行时查找、海量数据与事件绑定

对象查找、可增长集合展示或事件绑定进入本次范围时读取本参考。目标是让常用访问有明确成本，让大量数据逐步到达用户，让固定关系由可校验的数据声明；不是给所有小集合建立复杂索引，也不是把任意程序行为搬进配置。

## 先判断访问形态和规模

实现前确认当前量级、预期上限、增长速度、查询频率、更新频率、首屏时延、内存预算和对象生命周期。大数据功能给出可测的页大小、载荷/时延、渲染节点、保留段数、峰值内存和帧耗目标。区分三类操作：

- **固定依赖已有直接引用**：继续使用直接、序列化或注入引用，不额外增加 UID、注册表和字典。
- **调用方只持有身份，且需要重复找单个或一组对象**：使用稳定 ID 和拥有者维护的索引。
- **筛选、排序、聚合或批处理全部对象**：可以遍历拥有者已经持有的集合，但不能在每帧、每条渲染或嵌套循环中重复做同一查询，也不能临时全局发现对象来凑出集合。

很小且固定、只在初始化执行一次的集合可以直接遍历。选择最简单且满足实际规模的方案；没有量级证据时记录假设和验证点，不凭感觉制造全局缓存或通用查询框架。

## 按稳定 ID 和索引查找

- 需要按身份重复定位对象时，由集合拥有者提供 `Get/TryGetById` 一类入口，并维护字典、哈希索引、数据库索引或项目已有注册表。调用方不反复使用 `List.Find`、`First/FirstOrDefault`、按名称比较或手写循环查同一个目标。
- 一对多关系使用分组索引或项目已有查询入口；顺序展示与身份索引分开维护。索引是正式集合的派生产物，不成为第二份可独立修改的数据源。
- 对象增加、删除、换 ID、重新加载和跨作用域迁移时同步维护索引。明确重复 ID、缺失 ID、失效引用和重建行为；不能用一个更快但可能过期的表掩盖一致性问题。
- 查询入口区分“允许不存在”和“必须存在”，避免调用方拿到 `null` 后继续运行。热路径需要用项目 profiler、查询计划或基准数据验证，不把容器名称当成性能证明。
- 数据库或远程服务的查询条件应落到有索引的字段或正式查询 API；不能先取回全部记录，再在客户端按 ID 找一条。

## Unity 和相似运行时

- 固定组件和对象优先使用 Prefab/Scene 序列化引用、构造/初始化注入、父级明确传递或受控注册表；动态创建对象在创建和销毁时向拥有者注册、注销。
- Unity 运行时业务代码（含 Editor Play Mode）不得依赖 `GameObject.Find`、`GameObject.FindWithTag`、`GameObject.FindGameObjectsWithTag`、`Object.FindObjectOfType`、`Object.FindObjectsOfType`、`Object.FindObjectsByType`、`FindFirstObjectByType`、`FindAnyObjectByType`、`Transform.Find` 或同类按名称、标签、类型遍历场景/层级的 API 发现依赖。仅编辑器检查、迁移和制作工具可以使用；结果必须校验，不得把运行时查找用 `UNITY_EDITOR` 包起来就当作编辑器工具例外。
- `GetComponent`、其他框架的节点查询、DOM selector、依赖容器解析等允许的局部操作，不要在 `Update`、列表单元渲染或高频回调中重复执行。初始化时取得并保存所需引用；引用失效时通过明确生命周期重新注册或重建。此处的初始化缓存不适用于上一条禁止的 Unity 场景/层级发现 API。
- 不把“找到第一个同类型对象”当成依赖关系。多实例场景使用作用域、稳定 ID 或明确拥有者消除歧义。

## 海量列表和事件流

对话、消息、日志、事件、记录、资产等会持续增长的数据，不能以“一次全部读取、全部转换、全部创建 UI 节点”为默认实现。

1. **数据源先分段**：在数据库、文件索引或服务查询层读取，只返回列表所需摘要。时间窗口可用于分区或粗筛，翻页游标基于本次分页视图中稳定、唯一且有全序的键；不可变时间可参与 `(eventTime, eventId)` 复合游标，明确相邻页边界的包含/排除规则。追加流可用单调写入序号/摄取水位固定本轮集合，迟到入库数据由下一轮增量取得；可变列表的更新和删除需由快照版本或明确的增量合并/刷新处理，普通时间水位不能冻结它们。不能只靠 offset、可变显示时间或模糊时间段翻页。
2. **首屏先可用**：只加载当前可见段和少量预取。会话摘要列表与单个会话内的消息/事件流分别分页和虚拟化；事件正文或载荷按项展开，附件先取元数据，内容在打开时再加载。不能把“点开会话后再一次读完全部内容”当成渐进加载。
3. **表现层虚拟化**：复用列表单元或节点，只渲染可见范围；滚动加载不等于把已看过的所有 UI 对象永久留在内存。排序、筛选和搜索尽量在可分页的数据源执行。
4. **缓存有边界**：详情按作用域、稳定 ID 和数据版本缓存；列表段的缓存键还应包含查询条件、筛选、排序、方向、游标及快照/水位。海量数据必须设置容量/保留段数上限，可再配合时间失效；明确淘汰、刷新、失效和重建入口，失效前发出的旧响应不能在失效后重新写回。缓存不是正式状态。
5. **并发可收敛**：合并相同请求，取消离开页面或条件变化后的旧请求；每次查询或选择分配代次/请求身份，提交结果前同时核对当前查询键和代次，取消未成功时也要丢弃晚到结果。限制并发和预取范围。加载失败保留可重试边界，不把“没有更多”与“请求失败”混为一体。

验证至少覆盖首屏未读取或扫描全量数据、分页视图范围内无重复/遗漏、并发新增/更新/删除与迟到写入符合既定增量策略、稳定排序、快速切换条件后的乱序结果、详情按需加载、缓存失效，以及长时间滚动的请求量、渲染节点、内存和帧耗。按 A→B→A 切换并让旧响应最后返回，验证取消未生效也不能覆盖新状态；使缓存失效后再返回旧响应，验证不回写；检查正文/附件没有提前读取。阈值使用项目目标设备及数据规模，不在通用规范中硬编码一个条数。

## 配置化事件绑定

### 固定或可配置关系优先声明

- Unity Prefab/Scene 中已知的按钮、动画事件和组件回调，优先使用序列化引用及 Inspector/Persistent Event 配置，不在每次打开界面时重复 `AddListener`。
- 玩法、流程、页面或项目之间会变化的触发关系，由配置表、JSON、数据库、ScriptableObject 或其他项目数据源维护 `triggerId -> actionId + parameters`。程序提供经过注册的动作、参数 schema、权限和执行入口，配置决定使用哪些能力及如何组合。
- `actionId` 必须来自受控注册表或同类唯一入口。禁止在外部数据中填写任意类名/方法名后用反射执行，也不能把复杂业务代码、脚本字符串或安全边界绕进配置。
- 加载、构建或资源检查时验证目标引用、action ID、参数类型、重复绑定和作用域。配置失效时给出可定位错误，不静默跳过后假装功能已绑定。

### 动态关系仍由代码管理生命周期

运行时生成的列表项、对象池实例、临时订阅、状态相关回调和外部流事件可以由统一绑定器或代码建立实例关系。动态对象仍优先读取配置中的动作定义，不能以“动态创建”为理由，把可配置的业务动作重新写死。确需代码绑定时，绑定代码必须位于关系拥有者的生命周期入口，并明确：

1. 何时建立、何时生效、何时释放。
2. 重复进入、刷新或对象池复用时是否先清理旧绑定。
3. 使用订阅句柄、命名回调或项目统一机制完成对称释放；不要创建无法取消的匿名回调。
4. 销毁、禁用、场景/页面卸载、取消和异常后不再回调失效对象；迟到结果不能影响新实例。

配置化减少手写绑定与释放的数量，但不取消生命周期设计。静态序列化绑定由资源和宿主生命周期承载，宿主仍负责有效期检查，不能假设目标禁用后框架一定不会调用；动态绑定由绑定器或代码拥有者承载。同一关系不能配置一次、代码再绑定一次。

## 完成检查

- 用 ID 查询和全量遍历各自只出现在适合的访问形态；运行时固定目标没有 `Find` 旁路。
- 索引随正式集合变化而更新，重复、缺失和失效行为可验证。
- 大数据首屏、后续段、详情、缓存、取消和内存边界均有真实行为证据。
- 固定绑定可从 Prefab/配置查到，动作实现可从注册表追踪；动态绑定有成对生命周期并验证重复进入、复用和卸载。
