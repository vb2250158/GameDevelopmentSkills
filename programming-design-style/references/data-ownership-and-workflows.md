# 数据驱动与数据归属

用于新增或调整业务状态、内容、配置、流程、身份、缓存、存档及工具保存。先找到项目现有的数据格式、管理器、索引、编辑工具与加载方式，再决定扩展；不要另建第二套数据源。

## 业务定义由数据维护

业务状态、内容类别、条目、可调参数、资源映射和流程组合，设计时默认考虑新增、调整及不同用户或项目的差异。可能扩展的内容必须由配置文件、数据文件、数据库、游戏资源文件等数据源维护；不能硬编码在常量类、枚举、数组、代码字典或分支中，也不能等到条目多了才外置。

程序提供可复用的校验、条件判断、动作执行、组合调度和持久化能力；数据定义选择哪些能力、参数是什么、按什么条件和顺序组合。优先复用既有配置表、组件体系、行为节点或流程编辑器，不为一个小功能新造通用解释器。

以计划系统为例：

| 内容 | 拥有者与维护方式 |
| --- | --- |
| 状态集合、显示名、排序和显示方式 | 状态定义数据 |
| 用户或项目采用哪些状态、如何流转 | 作用域明确的流程数据 |
| 转换前提、权限条件与动作组合 | 规则数据引用已有校验和执行能力，由业务模块统一解释 |
| 计划当前状态、历史及保存结果 | 计划业务模块拥有的正式数据 |
| 校验、执行转换、持久化及通知 | 可复用的程序实现 |

新增“分析中”“待审批”等状态，或组合已有条件与动作，不应要求修改、重新编译业务代码。前端也不能另列状态清单，或通过状态名称字符串重新判断是否允许操作；读取统一入口提供的定义和可执行结果。显示名称可以变化，不能用作稳定身份。不同用户/项目的定义和实例必须归入正确作用域，不能互相覆盖。

游戏里的关卡、任务、奖励、动画和特效映射，以及组件、条件、效果和行为步骤的组合，同样按数据维护。表现资源从既有资源/表现配置查找，不在业务分支直接写资源名。

只有新增了现有执行能力无法表达的行为，才增加程序实现，并接入现有组合方式。更换私有排序算法、修改程序类型约束或接口实现，不等于新增业务内容；允许写代码，但不能借此把开放的业务状态集合固定成枚举。

参与跨模块引用的符号值必须有可追踪定义。固定的程序符号可使用命名常量、类型或受控入口；可扩展业务集合必须回到数据源。由数据生成的类型或索引是派生产物，不能手改成第二份事实。只有局部、一次性、不参与业务判断且无需调整的字面量可以就地保留。

## 唯一真源与真实修改

- 配置定义归配置管理器、索引或资源加载入口；默认值、缺失提示、校验和索引构建也由它负责。业务模块不临时解析另一套配置，不复制配置字段作为正式数据。
- 存档、账号进度和持久化状态归对应业务/存档拥有者；统一处理写入、回滚、迁移、同步和脏标记。调用方提交命令，不各自拼存档或直接改底层数据。
- 运行时实例只保存自身身份、必要状态和运行期差异，以及配置/存档引用键。配置攻击力与运行时加成是不同事实，不能把配置值复制进实例后任意修改。
- 默认按稳定标识通过拥有者查询、更新、删除。禁止“前端一份、后端一份”分别维护相同业务事实或规则，不能只修改前端对象后显示操作成功。
- 接口返回值、DTO、展示模型和缓存仅服务传输或展示，必须能从正式数据重建；正式结果由拥有者确认。复制或标注“只读”本身不能证明唯一真源成立。
- 缓存字段使用 `Cache`、`Cached` 或项目已有命名，明确来源、版本/时间、失效及重建责任。同进程共享引用必须来自同一个拥有者，不能独立修改或脱离更新机制；不把“只读共享”作为可任意长期持有配置的通用例外。
- 预览、草稿和过渡状态与正式结果分开。需要保存的数据必须进入指定正式数据源；失败时显示真实失败，不用本地值伪装成功。

新增字段时先判定：定义、存档、运行时事实还是表现配置；谁有最终解释权；当前保存的是引用键、状态、缓存、快照还是传输结果。说不清归属时不要先塞进当前对象。

## 身份按引用场景生成

- 配置文件已有稳定路径、资源地址、资源引用或加载键时，不额外添加 UID；经常移动的路径不能作为长期主引用。
- 配置内部条目需要被存档、其他配置、补丁或工具长期引用时，使用稳定子项 ID，由编辑器、导入或创建入口自动生成并持久化。显示名、数组位置和顺序不能承担身份。
- 运行时实例只有需要保存、同步、回放或长期追踪时，才生成独立实例 UID；不能把配置 ID 当实例 ID。
- GUID/UUID 或递增分配均可，但必须有明确作用域和受控生成器。禁止按当前数组下标或临时最大值随手递增；考虑复制、删除、分支合并和多人编辑后的稳定性。内部身份不要求人手填写。

## 工具保存和跨角色编辑

策划、美术、运营需要调整或批量维护的内容，通过已有数据/编辑器入口操作同一数据源。工具承担默认值、校验、批量操作和反馈，不要求人记住易错步骤。

编辑器、路线/地图工具、静态报告和调试面板中的项目数据“保存”，默认写入项目文件，使用 JSON、CSV、Markdown 或项目已有格式；项目已指定统一数据库/服务保存入口时复用该入口。浏览器 `localStorage`、`sessionStorage`、IndexedDB、URL 参数和内存只用于缓存、草稿或预览，不能被叫作正式保存。

浏览器工具通过已有文件接口、脚本或明确导出流程保存。无法写入时显示“已缓存/未保存到文件”，提供可导出的数据，不宣称保存完成。覆盖有价值数据时按项目约定保留可恢复备份或版本快照；这是数据保护，不是为已进版本历史的退役代码重复归档。多步生成的结果与上一步源数据分开，不静默覆盖来源。

## 按本次行为验证

- **数据扩展**：实际只改数据，新增一个状态、资源或已有能力的流程组合，验证加载、显示、校验与执行；不是只检查存在“配置类”。涉及多用户/项目时验证作用域隔离。
- **真实写入**：从调用入口执行一次修改，再通过拥有者独立读取；其他入口或重新打开界面得到相同正式结果。失败不能只留下前端假更新。
- **生命周期**：涉及缓存/身份时验证刷新失效、保存重载、改名/排序及重复 ID；涉及工具保存时验证重新打开后仍可读取正式结果。
- **错误数据**：按本次变化检查缺失资源、重复键、无效流转和不支持的能力引用，并通过统一入口报错。
