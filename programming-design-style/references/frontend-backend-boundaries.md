# 前后端与多端复用边界

任务涉及 Web、桌面、托盘、移动端、编辑器或其他表现入口时，用本参考完成设计与巡检。

## 职责归类

| 归统一业务入口 | 归前端 / 表现层 |
| --- | --- |
| 业务事实、状态含义、规则、权限、校验 | 布局、组件、颜色、动画、文案格式 |
| 查询与命令、持久化、迁移、跨端一致性 | 展开、选中、焦点、加载等短暂交互状态 |
| 会影响可执行动作或最终结果的派生 | 可从领域 DTO 重建的 presentation model |
| 后端失败、重试、冲突和离线同步语义 | 错误、缓存时间和不可用状态的展示 |

“后端”表示业务逻辑拥有者，不限定进程或网络形态；它可以是领域模块、共享库、Manager、Service、Repository、控制平面或 HTTP API。

## 开工前能力复用清单

新增表现端前，先给出：

1. 需求能力与业务事实拥有者。
2. 现有领域模块、Service、API、共享 DTO/Schema。
3. 其他客户端调用同一能力的路径。
4. 本次只需新增的适配、presentation model 和渲染。
5. 如需新建 Repository、业务 Service 或数据读取，现有统一入口无法扩展的证据。

没有第 5 项证据时，不得另起业务逻辑。

## 常见设计矛盾

- 前端直接扫描或写入由后端管理的文件、数据库、存档或运行时状态。
- Web、桌面、托盘、移动端分别解析同一业务数据或实现同一状态规则。
- 接入 API 后仍保留本地 Repository、旧类型或打包依赖，形成隐蔽双入口。
- view model 决定权限、业务状态、可执行动作、持久化结果或跨端语义。
- 只搜索目标前端目录，因附近存在旧旁路就继续扩展，没有检查统一后端和其他客户端。
- 项目文档描述旧做法，Agent 未用真实 API、调用链和提交历史交叉验证。

## 接口不足与失败处理

接口缺能力时，先扩展业务拥有者和共享契约，再让所有客户端复用。不要只给新前端增加旁路补丁。

后端不可用时，显示明确错误，或使用标明时间、只读属性和失效规则的缓存。不得静默切换为客户端直读底层数据。只有产品明确要求离线模式，并设计同步、冲突解决、权限和最终解释权时，才允许独立本地数据路径。

## 验证门禁

- 契约测试：所有客户端通过公开查询/命令得到一致业务语义。
- 架构测试：前端不导入受后端管理的 Repository，不直读业务文件/数据库。
- 依赖测试：Qt/React/Unity 等渲染层可以替换，业务模块不需要修改。
- 失败测试：后端不可用时不会启用隐蔽旁路或制造第二事实源。
- 打包检查：旧仓储、迁移前类型和本地数据解释器不再被强制打包。
