# 可视化设计报告

仅在用户要求可视化报告，或复杂关系确实需要独立图解时读取。普通代码规范审计仍直接对话输出。

## 内容

- 先展示实际当前结构与建议目标结构，标明数据来源、拥有者、正式状态、表现入口和真实协作方式；不能为单进程项目画出不存在的网络后端。
- 只画帮助读者判断的关系。当前/目标图可以覆盖多项相关发现，不为每项强制重复画图。
- 问题数量由证据决定，不凑 3–8 项。只有代码规范问题时不编造架构图。
- 每项复用巡检主文的证据格式，再说明哪些职责、数据定义或调用关系会变化，以及相应验证方法。
- 最后指出建议优先处理的问题与原因；已确认方案不再强制用户重新选择。

## 形式与文件

用户指定格式和位置时遵从；只需关系图时可在对话中使用 Mermaid。需要独立报告文件且未指定位置时，写到仓库外临时目录，以 `programming-design-review-<timestamp>.html` 命名，告知绝对路径。

HTML 使用自包含样式；模块依赖、调用链、状态流适合 Mermaid，其他关系可使用 HTML/CSS/SVG。不强制联网 CDN，确保目标环境能打开并阅读；环境支持时预览检查。没有用户需求，不为生成图表安装新工具或修改项目配置。
