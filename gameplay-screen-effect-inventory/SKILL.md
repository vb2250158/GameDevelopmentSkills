# 玩法画面清单 → 效果图张数

在画任何效果图之前完成这份清单。没有清单不得开画。适用于游戏功能效果图、UI 定稿与评审补洞；不依赖特定引擎。不授权改工程、出包或 QA。

与项目 UI 设计总入口（如星海 `panghu-design-unity-ui`）配合：本 Skill 只负责「流程与画面覆盖」；具体画图、批注、Prefab 实施仍走项目 UI Skill。

## 交付物

一次规划必须产出三样，缺一不可：

1. **操作→变化表**：每个玩家操作、结果状态编号、约束。
2. **画面清单**：每个需要单独表达的画面，含屏上信息与可点项。
3. **效果图张数结论**：必要张 / 可合并 / 可后补，并说明合并理由。

模板见 [references/inventory-template.md](references/inventory-template.md)。

## 步骤

### 1. 钉死主流程（先于画面）

用产品文档、现盘配置或已确认口径，写出玩家从入口到闭环的最短成功路径。至少包含：入口、主循环、领奖/结算、退出。数值未定时标「测试值/待定」，不编造正式数值。

### 2. 列操作与状态编号

对主路径上每个**玩家可点动作**与**服务端驱动变化**编号：

| 字段 | 要求 |
| --- | --- |
| 编号 | 稳定短码，如 `S0`、`S3`；同一功能内不复用 |
| 操作 | 玩家点什么，或「倒计时到点」这类非点击触发 |
| 变化到 | 进入哪个画面/状态 |
| 约束 | 何时不能点、扣什么、是否互斥 |

同屏内仅选项高亮变化（如选中第 2 只动物）一般**不新开状态编号**，记在「同屏更新」即可。新编号只给会改变主布局、主 CTA 或关键信息结构的状态。

### 3. 列每个画面的信息与点击

对每个需要单独表达的画面写：

- **屏上信息**：标题、进度、列表、倒计时、空态文案等玩家必须看见的内容。
- **可点项 → 去向**：每个控件点后到哪个编号；禁用/隐藏也要写明。
- **与邻态差异**：相对上一态多了什么、少了什么、主按钮变成什么。

### 4. 决定效果图张数

默认：**一个会改变主布局或主 CTA 的状态 = 一张效果图**。

| 判定 | 做法 |
| --- | --- |
| 布局/主按钮/关键信息结构不同 | **必要张**，必须出图 |
| 仅选中高亮、数字变化、同布局不同数据 | **可合并**进邻态图，清单里注明用批注说明 |
| 通用弹窗已有项目标准（恭喜获得等） | **可后补**或复用标准弹窗，不占玩法专属张数 |
| 失败/缺项提示 | 清单写清文案与引导；默认不单出图，除非产品点名 |

输出格式：

```text
必要效果图：N 张 — [编号列表]
可合并：…（理由）
可后补：…（理由）
```

不为「显得多」而拆张；也不为省事把旅行中/可领取/闲置压成一张。

### 5. 开画门禁

同时满足才允许制作效果图：

- 操作→变化表已覆盖主闭环；
- 每张必要图都写清屏上信息与可点去向；
- 张数结论已写出；
- 用户未要求改编号，或已按用户改定编号。

开画后仍走项目效果图制作规范（横屏、生成图、批注成对等）；本 Skill 不替代画图规范。

## 禁止

- 流程未清就先出效果图。
- 效果图漏掉主 CTA（例如地图闲置没有「开始旅行」）。
- 用 HTML/竖屏临时板当权威定稿（除非用户明确只要示意）。
- 把测试数值写成正式数值。
- 把效果图完成说成功能已落地或 QA 已过。
