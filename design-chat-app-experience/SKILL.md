# 聊天产品体验

围绕用户可识别、可返回的会话组织产品。先看当前界面与实现，区分实际能力和推测；只读审查交付证据，改动按用户授权实施。

## 先确定身份和事实

按 [会话与投递合同](references/conversation-contract.md) 核对 Conversation、Participant、Message、ReadState 与 DeliveryState 的现有拥有者和稳定身份。账号、收件人、角色、设备与传输路由的职责分别说明，显示名称和全局下拉选择不能成为隐含消息归属。

领域事实与写入遵守 [编程设计](../programming-design-style/SKILL.md)；用户文案和导航遵守 [面向用户设计](../design-for-users/SKILL.md)，加载和等待遵守 [流畅交互](../design-responsive-interactions/SKILL.md)。本技能不另定义一套数据归属、分页或重试框架。

## 界面职责

| 界面 | 主要职责 |
| --- | --- |
| 会话列表 | 稳定名称/头像、最近消息、时间、未读及可信状态；选择会话 |
| 会话详情 | 当前会话身份、消息、输入、发送/重试及该会话动作 |
| 收件人选择 | 创建或打开明确会话，保留原会话身份 |
| 设置与连接恢复 | 全局配置、检测、字段说明及诊断入口 |

紧凑屏幕通常列表进入详情，大屏可并排；返回保留列表位置、筛选和草稿。通知跳转到对应稳定会话，收到其它会话消息不能自动切走当前页面。产品确有其它模型时按当前合同选择，不强制新增实体或导航框架。

## 展示、加载与恢复

- 先显示分页摘要，进入会话再加载对应消息，正文与附件按需读取；不能把全量读取包装成前端分页。
- 未读按用户/账号与会话维护。只有对应内容实际呈现后，才按产品规则推进读取位置；打开 A 不清 B，打开进程或收到通知不等于已读。
- 发送状态只显示协议能证明的结果。未知结果先对账，保留原消息身份，不能把超时直接当未发送后重发。
- 离线能力只在产品承诺且已有同步设计时使用本地持久投影；服务端事实仍由其拥有者决定。失效身份/权限的数据不可因缓存可用而继续展示。
- 加载、空、部分异常、离线、发送失败和配置错误分别呈现。保留有效内容与输入；单条损坏不应无故阻断整段会话或列表。
- 配置先可靠发现和预填，字段旁解释来源、格式和失败恢复；技术详情按需展开，不让教程代替清楚的界面。

## 匹配验证

按改动覆盖：A 打开时 B 到消息；打开 B 后只更新 B 已读；通知直达 B；返回恢复原列表位置；离线或未知结果发送；恢复/重启；切号；长消息和大数据分页；大字、键盘与窗口变化。收到、发送、已送达与已读逐层举证，不用一次截图证明投递可靠。
