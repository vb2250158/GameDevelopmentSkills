# 会话与投递合同

## 归属与持久化

会话 ID 由现有业务拥有者提供，关联账号、参与者及需要的线程上下文；重命名不改变历史归属。消息拥有稳定 ID 和会话关联，读状态按账号/会话维护。消息修改、撤回及附件遵从现有协议，不假定消息记录不可修改。

界面观察正式拥有者提供的投影，传输标识与显示名分开。离线产品可以从可重建本地持久投影读取，由同步层负责与服务端协调；本地不是另一套独立正式事实。重复接收去重、顺序及补拉沿现有协议，不依赖显示文本相同。

## 投递与读取

排队、发送中、服务端接受、目标送达和已读含义各自明确；这些名称是示例，不是封闭的业务状态枚举。协议不支持时不展示。传输结果待确认与确定失败分开，恢复先用原消息/投递 ID 查询回执，再判断是否允许重试。

自动重试仅用于当前协议已证明可重试、且有稳定身份或幂等保证的操作，并沿现有有界机制执行。不能为追求表面成功额外发送一份消息。

接收保存到对应会话后更新摘要和未读投影；UI 订阅变动。读取水位由实际呈现推进，远端已读回执与本地“标为未读”分开。新消息、通知、进程启动各自不直接清除全部未读。

## 从全局收件人筛选迁移

先恢复消息原有身份与上下文映射，处理歧义记录，再引入会话投影。稳定 ID 保留，不能按显示名强合并，也不能因切换下拉框把历史归到新收件人。迁移验证接收、发送、草稿、通知、返回及重启，旧入口按编程设计的退役规则收尾。
