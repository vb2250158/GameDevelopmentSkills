# 游戏自动化执行与复核

从用户指定的工作目录或当前项目入口发现执行器、策略、状态和日志。不要猜测个人盘符、游戏列表、渠道、模拟器或每日刷新时间；这些由实际项目配置提供。

## 运行前

1. 核对本轮目标游戏、日常或周常范围、用户授权及禁止动作。未明确授权的购买、抽卡、交易、账号变更和不可逆选择不执行。
2. 找到项目真实的 dry-run、执行、状态查询和人工接管入口，读取参数与失败行为。缺少执行器时只完成可做的调查，不能声称技能已提供该能力。
3. 核对人工接管、并发锁、当前游戏进程和待恢复状态。同一桌面一次操作一个游戏，不抢占用户窗口，不结束无关进程。
4. 首次或输入有变化时预览执行范围。授权与范围均明确后继续执行，不重复询问同一许可。

## 执行与恢复

- 出现登录、验证码、协议确认或需要用户选择账号时，按项目入口登记人工接管，保存现场并暂停依赖该操作的步骤。用户完成后明确恢复原任务，不重建重复队列。
- 使用执行器已有的取消与恢复方式。只有策略标记为可恢复的错误才有限重试；重复失败读取新日志、改变方法，不用循环启动掩盖失败。
- 默认保留现有软件与游戏渠道。安装插件、代理、模拟器或改变网络不因自动化失败而自动获得授权。
- 日常与周常分别判断，按配置的时区和刷新时刻划定本轮日志；不把历史完成记录计入本轮。

## 完成条件

完成需要当前运行对应的权威日志或可独立回读的游戏结果，同时不存在同轮失败条件。脚本退出码为零、进程结束、截图成功或窗口打开只能证明相应动作。

报告目标、实际运行、完成证据、仍未完成项及原因。缺少证据时保持待复核；人工接管期间保留现场，禁止清理用户正在操作的窗口。

修改执行链时读取 [工作流合同](references/workflow-contract.md)，复用项目已有验证入口。共享技能不规定具体游戏业务规则。
