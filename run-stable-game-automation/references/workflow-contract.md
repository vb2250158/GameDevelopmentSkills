# 自动化工作流合同

用于检查现有执行器是否具备可恢复、可验证的运行方式。这是接入要求，不是本仓库已提供的 API。字段名与退出码沿用实际项目定义，不为适配技能另建一套状态。

## 应能定位的入口

- 策略：目标游戏、允许和禁止动作、执行范围、刷新时刻、重试分类。
- 预览与执行：能显示本轮准备做什么，并只在已有授权内执行。
- 状态查询：记录游戏、周期、运行身份、开始结束时间、完成或失败证据。
- 人工接管：开始、到期、显式恢复；接管期间不得点击、抢焦点或清理用户进程。
- 并发控制：同一桌面只有一个操作者，明确锁归属和释放责任。
- 验证：使用项目已有的回归与证据复核入口，不虚构工具名。

## 证据与恢复

1. 每次运行记录新的身份和日志范围，避免把旧日志用于完成判定。
2. 日常和周常状态独立，当前周期由项目配置计算。
3. 完成条件来自游戏实际结果或权威工具日志，状态界面只展示这些结果。
4. 明确区分已完成、待复核、人工操作、失败和取消；未知不是成功。
5. 有界重试使用同一事项的恢复记录，确认上次操作是否生效后再决定是否重试。
6. 失败、取消与超时均释放当前任务拥有的资源；他人资源和有效人工接管现场保留。

## 变更验证

验证至少覆盖本次触及的成功、失败、取消或恢复路径。只改文档时检查引用和语义；改并发或状态规则时验证真实行为。没有可运行的执行器时写清缺少的入口和未验证范围，不用静态阅读代替运行证据。
