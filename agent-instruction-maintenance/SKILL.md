# 维护 AI 指令入口

让入口在读取预算内完整载入，让专项规则在实际需要时可找到。保留用户授权、行为边界和验收要求，不以压缩字数为由删除约束。

## 核对现状

1. 确认本次是检查还是已授权修改/提交。检查精确 Git 或 SVN 差异与归属，保留无关内容。
2. 读取生效的全局与项目入口、覆盖文件及 `project_doc_max_bytes` 配置；用 UTF-8 字节数衡量自动读取预算，不把行数或字符数当作 token 数。
3. 对照当前会话注入的末尾与磁盘文件，判断是否截断；不能仅凭文件存在或链接正确就说模型已经读到。
4. 列出固定候选：入口、实际调用它们的技能、引用和校验器。不遍历无关仓库或把个人技能全量发布。

## 决定放在哪里

- 全局入口：跨项目必要约定，以及语言、设计、执行技能的触发条件。
- 项目入口：项目身份、必要安全与授权边界，以及任务到技能的直接路由。
- 现有技能：已有明确归属的详细规则，优先补入该技能。
- 新技能：有独立任务用途、能够被准确触发且没有现有归属的可复用流程。
- `references/`：仅特定模式需要的长流程、接口、证据和例子；入口注明何时读取，不要求每次全读。

## 迁移与发布

- 建立旧段落到目标技能/参考的映射，逐项核对语义；删除的重复内容也必须能指出保留位置。
- 更新直接调用入口、相对链接、章节锚点、清单及对应校验源路径；不能把正文搬走后仍让检查器只查旧文件。
- 公共仓库只放通用规则。私有项目名、业务、服务地址、凭据、账号配置与机器路径留在私有环境。
- 标题、描述、正文、参考说明使用中文；技能标识、文件名、命令和 API 字段保持兼容。
- 入口预算建议：全局不超过 4 KiB、项目根不超过 8 KiB，并为子目录规则保留空间。这是团队维护目标，不是模型的官方性能阈值。不能仅靠提高读取上限掩盖重复规则。
- 核对 UTF-8、技能格式、迁移映射、引用可达性、已配置加载路径与相关规则检查。纯文档不新增测试；加载逻辑改变时运行有意义的现有行为验证。
- 已授权发布时只提交本次文件，回读 Git/SVN 版本与内容；团队更新公共仓库和项目即可获得修改。全局本机文件须另外更新，不能声称 Git 拉取会自动替换个人配置。

全局入口示例见 [模板](references/global-AGENTS.md)。首次使用前确认所引用技能已就位；用户已有设置先检查差异再合并，不覆盖账号配置。
