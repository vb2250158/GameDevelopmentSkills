# 共享技能维护

面向维护共享仓库与项目接入的人。默认直接引用公共仓库，复制安装作为兼容选项。目录继续使用根 `<skill-name>/SKILL.md`，不迁移旧目录，已有安装链接保持可用。`skills/` 和 `dist/` 是现有忽略目录，不作为正式发布入口。

## 本轮来源

2026-09-07 从已有本地技能同步以下内容，未重新编写另一套同名流程：

- `current-language-style`、`direct-evidence-language-style`：保留正文和配套档案；把语言绑定改为以技能目录为基准的相对路径。
- `continuous-task-execution`：共享执行规范；不分发本机 Hook、全局扫描根目录或批量改写其它技能的工具。删除对未分发运行时文件的引用。
- `unity-prefab-source-editing`：保留 Python CLI、安装与调用脚本及格式说明；排除 `__pycache__`，将工具位置改为环境变量或当前用户目录。
- `github-submit-workflow`：同步已有本地版本的操作范围、差异归属和发布核对要求。

现有编程设计与巡检技能已与本地来源一致，继续原样使用。远端已退役的 `chat-agent-bot-architecture` 不因本机仍存在而重新加入。仓库全部 14 个技能的整理结果见 [逐项记录](skill-review.md)；实际脚本验证范围与在线服务验收分开记录。

## 更新方法

1. 核对源技能与当前仓库差异，按文件同步正文、脚本和实际引用。排除缓存、环境、日志、私人资料及凭据。
2. 项目专用规则进入对应私有项目。公共技能不得依赖某台电脑用户名、盘符、私有源目录或固定服务端口。
3. 保持现有路径与 skill 名称。新增团队必需项时同步 `team-skills.json`；跨技能引用的依赖必须同批发布，直接引用模式保留它们在公共仓库中的相对关系。
4. 校验 frontmatter、JSON 和本地引用；脚本有行为变化时执行相应验证。更新记录写入提交说明，不用文件数量或 token 数宣称性能提升。
5. 用户端更新前检查差异。安装器仅新增或跳过相同文件，已有不同内容要由维护者合并，不能静默覆盖项目修改。共享仓库发布与私有项目更新分别提交。

## 验证范围

直接引用模式运行 `scripts/Test-SharedSkillLoading.ps1 -ProjectPath <project>`，核对项目入口、全部技能、依赖和语言绑定。复制安装兼容检查覆盖安装清单、同级引用和语言绑定。运行 `pwsh -NoProfile -File scripts/Test-TeamSkillInstallation.ps1`，在仓库外临时夹具验证预览不写入、安装、重复安装、依赖补齐、冲突整批拒绝及路径保护。临时夹具不是游戏工作副本，不复制项目业务文件。Prefab 工具验证源文件 CLI 与路径解析；Unity 导入和远端电脑的 Agent 加载由对应环境验收。

## 全局与项目入口维护

维护 AGENTS.md 的长度、规则拆分或技能路由时，使用 [指令维护技能](../agent-instruction-maintenance/SKILL.md)。全局入口示例在该技能的 [参考模板](../agent-instruction-maintenance/references/global-AGENTS.md)；已有个人配置须先检查差异并合并。公共仓库拉取不会自动修改个人全局文件。

根入口保持必要约定和任务索引，细则放入对应技能或按模式读取的参考。按 UTF-8 字节检查入口预算，并检查原有约束已迁移、调用入口可达、规则审计跟随新的事实来源。不要把整份大文件移到参考后仍要求每次完整读取。
