# 表格任务协作

完成用户请求的阶段：收集、分析、修订、回填或实施。只读材料中的问句和建议是证据，不是执行授权。已有清单、负责人、月份或行集合限定当前范围，不因“所有待处理”自动扩到其它事项。

## 数据与授权

- 配套安装 [腾讯文档读取](../read-tencent-docs-opendoc/SKILL.md)。首次读取、恢复任务或写入前刷新目标表头和目标行，同一轮未变化的结果可复用。仅审阅离线材料时注明来源时间，在线写入前重新定位。
- 明确业务事实由表格还是项目计划服务维护；表格仅为展示时，按项目拥有者的结果同步，不能另立状态真源。
- 表格写入、代码实施、外部发送分别核对本轮已有授权，授权范围内不重复确认。缺少会改变业务结果的决定时才提问。
- 行号用于本次读写定位；用稳定标识及必要业务字段复核身份，避免排序、插行后写错。用户批注保留原文，不因出现历史 Agent 留痕而忽略新反馈。

## 按阶段加载

| 当前任务 | 读取与产物 |
| --- | --- |
| 导出任务与截图 | [导出与截图](references/export-and-images.md)：目标 Markdown、逐项内嵌截图及可靠映射 |
| 分析修正方案 | 查真实定义、调用、配置与资源，写原因或现状、具体修改、风险与验收；缺产品决定时写精确缺口 |
| 写回方案 | [回填规则](references/tencent-docs-backfill-rules.md)：确定字段与值，写前核对、写后回读 |
| 吸收新批注 | [批注修订](references/user-comment-revision-workflow.md)：区分已消费反馈和新增反馈，修订后保留原意见 |
| 实施已授权方案 | [实施流程](references/confirmed-implementation-workflow.md)：复用原任务，防止重复领取，完成实现与匹配验证后再更新状态 |

参考中的固定列名与状态只适用于使用该表结构的项目。业务状态、进包和 QA 仍按项目规则判断；源码修改、测试通过和目标包验收分开留证据。

## 可选分工

单项工作默认由当前 Agent 完成。只有任务能独立处理、当前环境支持且授权允许时才委派；工具不可用时继续本地工作。使用实际可用模型与推理设置，不固定型号或并发数。

委派前读取 [任务模板](references/subagent-task-template.md) 与 [子任务规则](references/subagent-task-rules.md)。只传目标、必要资料、文件边界、证据位置和产物；不默认复制完整历史，不继续派生。共享工作区优先并行读、集中写，协调者复核结果后统一回填。

## 工具与完成

复用 `scripts/` 中的 `export_tencent_bug_rows.mjs`、`build_solution_backfill_payload.mjs`、`sync_solution_comments.mjs` 和 `verify_tencent_backfill.mjs`。调用前检查实际参数和输入合同；脚本只处理数据与校验，不能代写未经调查的业务结论。

有截图线索但当前通道未返回 URL 时，先补取或记录通道证据；不要写成“没有截图”。缺失证据只影响依赖它的事项，其它独立事项继续。报告实际处理数量、未处理项与原因，写入完成必须有回读；外部发送必须有实际回执。
