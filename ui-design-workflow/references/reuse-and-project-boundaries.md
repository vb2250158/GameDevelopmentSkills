# UI 复用与项目边界

## 找到正式入口

任何涉及界面的改动，先读取当前项目 UI 入口和配置。覆盖代码重构、参数、事件、文案、序列化引用、隐藏节点、布局及动效；只传参数也需核对实际显示与交互。项目没有统一配置文件时使用已有文档与组件入口，不为使用本技能另造配置框架。

1. 写清用户需要知道的状态、动作、显示时机与结束条件。按实际结果依赖决定阻断范围，短暂后台恢复不自行升级为常驻条或确认弹窗。
2. 沿当前调用点查找完整 UI：确认框、消息、加载、选择、输入或状态提示。读取候选 API、参数类型、默认值、生命周期和正式调用，不凭名称或当前目录断言不存在。
3. 与可用的同类正式界面对照组件和样式，记录满足的职责与精确缺口。参考数量以实际存在为准。

| 现有能力 | 处理方式 |
| --- | --- |
| 完整入口满足语义、时机和生命周期 | 调用正式入口传参，保留同一套内部组件 |
| 职责相同，仅缺可复用参数 | 最小扩展原契约，保持旧调用默认行为，验证旧调用者 |
| 确无合适完整入口 | 说明候选及缺口，用项目基础组件组合；重复单元沿正式复用机制维护 |

“希望常驻”或“不占用确认框”先作为生命周期需求核对，不能直接推导为新建显示系统。项目允许的低层图元用途仍可使用，不把某项目的组件禁令套到所有项目。

## 参数和生命周期

- 业务拥有者提供事实和结果；UI 接受显示及交互参数，不复制存档、网络、奖励或权限规则。
- 核对正式参数类型，使用已有本地化、图标、字体与颜色标识。必要新参数先扩展契约，不编造 API。
- 重复显示、刷新、关闭重开、对象池复用、切号和换场景时清理旧状态及回调。异步结果只提交到所属请求与界面代次。
- 多来源请求沿既有队列、实例或句柄协调；不能清空其他业务状态。操作锁按编程设计技能的锁组和逐次句柄规则处理。
- 文案、状态、尺寸和资源用项目数据或组件变体表达，避免业务侧散落样式和坐标常量。

## 项目持有的事实

项目保留设计语言、视觉 token、字体、素材目录、窗口基类、通用组件、平台与适配范围、截图入口、测试与提交方式。不要把产品导航、品牌色、固定圆角、窗口尺寸、某次故障或历史实验限制发布成通用规范。

迁移到共享技能时记录“原段落 → 通用条款 → 项目保留项”，原路径继续作为项目适配入口。使用项目现有清单与证据记录，不重复建立台账。

## 对应验证

按实际改动核对正常、失败、恢复、重复触发、关闭重开、长文案及目标比例。跨页面提示再检查遮挡、层级、输入穿透和消失条件；通用入口扩参再检查旧调用默认表现。空白条、文字不可见、回调串用或无本轮运行证据时，准确标记未通过层级，修复后重跑受影响检查。
