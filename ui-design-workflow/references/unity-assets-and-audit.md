# Unity 素材、复用与自检

## 范围与事实

记录限定工作区与目标资产差异，保护未提交改动，核对正确 Editor、工程、版本和 Console 基线。先查目标、嵌套依赖与可用的同类正式 UI，局部证据不足再扩大检查。使用已配置的工具；空的扫描命令不代表存在可执行扫描器。

实际 API、正式文字/按钮/关闭/红点、字体、本地化、颜色状态与资源使用项目指定入口。需要新颜色或组件时先说明现有能力的缺口。路径、GUID、border、Image.type、RectTransform 和交互状态来自当前资源，不从文件名或旧快照推断。

## Sprite 与尺寸

按节点职责、目标尺寸、border、留白及正式视觉比例选材。需要九宫格拉伸的底框使用适合该职责且有有效 border 的 Sprite 与 `Image.type=Sliced`；仅设置 Sliced 不能补出 border。

目标尺寸需满足边框及中心区域的空间要求，必要时改用合适变体，而不是把胶囊、圆形或小确认框强拉成大矩形。比较圆角、描边与投影比例。完整插画、背景、图标、人物等按资源用途使用 Simple 或项目验证方式，不能全部改为 Sliced。

## 复用与状态

重复职责的单元先选择正式 Prefab、Variant 或模板；必要新单元说明候选、结构差异与复用缺口，再由父页面实例化，不复制成多套散装层级。

记录目标单元来源、实例数、核心字段的 owner/字段名/真实目标、列表模板、状态映射与点击入口。隐藏节点同样核对；每个状态职责明确且可达。清理无用旧节点、重复状态和失效关联，用户差异与旧逻辑退役按编程规范保护。

## 结构变动后的关联恢复

1. 固定当前美术版本与差异，保护现有布局及资源。
2. 从原 Prefab、有效版本、嵌套来源或任务基线取回字段原目标、类型、path/fileID 与来源。基线不足时标明待确认，不猜测创建。
3. 沿字段真实用途、刷新和点击链判断职责，不只看名称。
4. 分类当前变化：移动、改名、重挂、拆并、替换、删除或 override 失效，记录前后对应证据。
5. 优先重新关联当前同职责对象；合理拆并时最小调整契约。仅当职责确实缺失且当前组件无法承接时创建最小对象。
6. 继续检查同一控制器的全部必填引用、模板、状态与按钮事件，不只修第一个异常。

不要恢复整套旧层级覆盖美术调整，不用运行时 Find、静默创建或按旧名字重建来掩盖关联丢失。

## 最终资产与运行检查

使用项目现有清单，保存修改后的目标路径、时间/版本/差异基线、检查时间和返工轮次。缓存层级、旧图和旧检查不能证明当前版本。

- 结构：职责、命名、嵌套来源、Variant/Override、重复/无用节点。
- 关联：必填字段、列表模板、状态、事件、Prefab fileID、Missing Script/Object 与空引用；恢复记录包含原因和真实替代目标。
- 视觉与布局：正式组件、文字、按钮完整状态、字体、颜色、Sprite/border、尺寸、锚点、裁剪及缩放。
- 行为：覆盖要求中的页面与状态，运行真实点击链；列表按缩放与输入参考验证，不能只证明静态绑定存在。
- 证据：最终运行画面、目标比例、相关备用比例、同一会话最新 Console 和 run ID/时间；对照同版本目标图与数据，检查差异。

发现项区分必须修复、警告和有证据的例外，写清影响和范围；不能为交付降级问题或用“以后处理”作为例外。修复后按影响重新检查最终保存状态，项目要求每次完整自检时执行该完整流程。结构与运行分别报告，任一未验证时不能合并声称完成。

不为截图操作未授权的真实玩家数据，不通过删除、禁用应验 UI 隐藏未完工内容。正式范围排除与版本控制、构建、目标包、QA 结论分别按项目授权及证据处理。
