# Unity UI 实施与验收

先读取项目 UI 组件、资源、窗口架构和测试规范，再选择 UGUI 或 UI Toolkit。图像方案、工程资源和实际运行分层验证；用户已授权的阶段连续执行。

涉及资源制作、层级迁移或 Prefab 保存时，再读 [素材、复用与自检](unity-assets-and-audit.md)；适配和输入使用 [缩放与滚动](unity-resolution-and-input.md)。同一事实按这些参考维护，项目文件只补充正式组件和更具体的合同。

## 组件与引用

- 沿项目窗口入口核对创建、参数、绑定、显示、关闭和销毁。复用完整窗口及正式控件；同职责的重复单元使用正式 Prefab、Variant 或模板，不在父资源散装复制多套业务 UI。
- 修改前保存当前差异和可恢复快照。美术调整层级后，比较原资产、当前资产、字段用途与版本差异，将引用关联到承担同一职责的现有对象，避免看到空引用就重建组件。
- 固定引用与事件优先由序列化资源或配置维护；动态绑定明确拥有者、解除及对象池复用规则。运行时不使用全场景 Find 弥补丢失引用。
- Sprite、九宫格、字体与颜色来自实际资源和项目配置。生成图与占位图不证明正式素材存在。

依据效果图实施时，固定同版本状态覆盖清单、无标注目标图、标注 JSON 与批注图，分别说明视觉目标、状态覆盖、空间规则和标注依据。核对目标比例、不可改部分与允许调整的内容；不一致时先修对应依据。美术资源待补时，可在已授权范围搭建已有组件与结构，但保持缺项记录，不能用整张目标图加透明按钮冒充实现，也不能把批注图作为正式美术资源。

## 滚动与布局

UGUI 的 `ScrollRect.viewport` 指向 Viewport，`content` 指向其下的 Content。Viewport 使用项目已验证的裁剪组件。布局组件、尺寸适配器、锚点和脚本在每一轴上有明确的尺寸拥有者，避免互相覆盖。

动态垂直列表若采用 `ContentSizeFitter` 按内容定高，核对 `Vertical Fit=Preferred Size` 与布局职责；虚拟化、手动高度或其它方案按其实际合同验收，不强制套用同一组件。溢出时 Content 尺寸与滚动范围必须覆盖真实内容。

先按内容关系、排列方向、动态数量、换行和尺寸约束选择 Layout Group、嵌套布局或独立锚点。同行图文通常用 `HorizontalLayoutGroup`，上下用 `VerticalLayoutGroup`，规则重复单元可用 Grid；HorizontalLayoutGroup 不自动换行。独立锚定或独立动效的节点不必强放同一组。

明确 Padding、Spacing、Child Alignment、Control Child Size、Use Child Scale、Child Force Expand 与 LayoutElement 的职责。图标保持比例，文字按合同占剩余空间；出现隐藏项占位、循环撑大、间距跳变或持续重排时修正尺寸拥有权，不用临时偏移掩盖。测试短长文本、多语言、空值、隐藏/禁用、动态增减和相关屏幕比例；根节点不是一律固定尺寸或一律拉伸。

大型集合从数据源分页、按需读取详情并限制渲染节点与缓存；视觉上能滚动不证明未全量读取。参照编程设计的集合与查找规则。

## 动效播放链

追踪显示调用 → Motion/调度入口 → 运行时控制器 → 目标节点 → 子动画组 → 完成回调。控制器挂载位置以真实查找方式为准，不能只凭 Prefab 存在 Tween 组件认定可播放。位置终点来自实际节点坐标与布局合同，避免额外缩放。

检查目标、组标识、包含子节点、排除规则、最终停止位置与取消。覆盖首次打开、复用重开、打开中关闭、关闭中重开；迟到回调只影响所属播放代次。具体基类、Motion 和 Tween 类型由项目维护。

## 保存后的检查循环

1. 最后一次保存后检查真实资产：组件来源、嵌套复用、序列化引用、事件、状态映射、裁剪与输入。
2. 在目标 Editor/包进入必要状态，取得同一版本 GameView 与 Console 证据。检查点击链、首尾滚动、遮挡、字体、适配及失败恢复。
3. 对照目标图和标注数据检查空间误差；需要缩放时记录转换，不以实现中的常量反证自身正确。
4. 修复必须处理的问题，保存后重跑受影响静态与运行检查；变化影响全局布局或引用时重新检查整个目标资源。

使用项目测试入口及现有清单。编译、YAML 检查、方法测试、包内存在和一次截图不能互相替代。缺少 Editor 或目标设备时交付已验证的文档/静态层，并明确运行层未验证；本技能不要求另建工具或测试框架。
